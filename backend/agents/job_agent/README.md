# 求职智能体

`job_agent` 由 `base_agent` 的图、状态、节点、工具、Schema、错误和提示词结构复制而来，拥有独立实现目录。通过 `backend/bootstrap/runtime.py` 注入模型与 PostgreSQL Checkpointer，并复用共享 Agent Runner、会话、题卡和 SSE 协议。

## 当前能力

- 在同一会话中进行多轮求职相关对话。
- 模型生成期间通过共享 Runner 发送 SSE `message.delta`，完成后发送消息快照。
- 用户提出与求职无关的问题时，说明求职助手职责并引导用户提供求职相关信息；问候和混合请求按提示词中的边界处理。
- 需要关键选择时使用 `ask_user_questions` 单选题卡，等待用户作答后继续运行。
- 根据用户在对话中明确提供的资料，由模型自主提出最多三个岗位方向及匹配依据，调用 `recommend_job_roles` 校验后回答；生产代码不维护固定岗位列表。
- 缺少关键资料时先追问；经验区间可使用单选题卡，需自由描述的信息通过普通对话收集。年龄不能作为推荐依据。

求职助手可按需读取固定主体下已保存简历中的求职事实，但不能读取未保存草稿或修改简历；此能力只适用于本机或可信私有网络部署，不提供多用户简历隔离。当前没有实时职位检索、投递和外部平台接入。推荐结果只是岗位类型建议，不是具体招聘职位。模型无法给出有依据的建议时会说明信息不足，不编造结果。

用户要求诊断或评估本人简历不足、缺失或改进空间时，求职助手会先读取已保存简历，再根据实际返回字段分析；一般简历知识咨询和单纯片段润色不会单独触发读取。简历未体现的信息不会被推断为用户没有相关经历；没有已保存简历或读取暂不可用时，会说明情况并请用户提供材料。

## 代码边界

`factory.py` 创建 `JobAgent`，`graph.py` 连接 `input_node → agent_node → tool_node/output_node`；`prompts/` 定义求职助手身份和行为；`tools/` 提供结构化追问和推荐校验工具；`recommendation/` 保存资料、模型建议和校验结果的 Schema 与校验逻辑。后续业务能力以独立模块实现，通过工具和工厂接入，不复制共享 Runner。

增加其他求职能力时，创建独立业务模块和工具，在 `factory.py` 注册并更新提示词。岗位名称由模型根据对话生成，不访问实时招聘平台。
