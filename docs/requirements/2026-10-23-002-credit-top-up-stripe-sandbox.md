# 积分充值与 Stripe 沙盒支付需求

## 1. 需求背景

NexusAI 已有积分余额、对话扣费和退款功能，但没有充值入口。用户希望通过 Stripe 沙盒支付，为自己的账号增加可用于对话的积分。

## 2. 需求目标

让已登录用户在积分余额旁发起充值，选择支付币种并输入金额，完成 Stripe 测试支付后获得积分。

## 3. 当前功能现状

- 登录后的账号栏在 `frontend/src/App.tsx` 显示积分余额；余额来自 `GET /api/auth/session`。
- `backend/app/models/credit.py` 中的积分账本目前只记录注册赠分、对话扣费和运行退款。项目中未查到充值或 Stripe 支付流程。
- 当前每轮新对话扣 1 积分，失败或主动取消后退回 1 积分。

## 4. 详细功能需求

- 在账号栏积分显示旁增加“充值”按钮，仅已登录用户可使用。
- 点击按钮后弹出充值界面，用户选择当前 Stripe 沙盒账户可用于该支付流程的币种，并输入正整数金额。
- 界面根据输入实时显示将获得的积分数量，并在底部显示支付币种及应付金额。无论选择哪种币种，均按金额数字 **1:1** 换算积分；例如支付 10 USD 或 10 CNY，均获得 10 积分，不按汇率换算。
- 输入无效，或金额低于 Stripe 对所选币种适用的最低支付额时，不能发起支付，并显示原因。参见 [Stripe 币种与最低支付额说明](https://docs.stripe.com/currencies)。
- 点击“支付”后跳转至 Stripe 托管的沙盒支付页面。支付确认成功后，给发起充值的账号增加对应积分；刷新页面后积分仍可用，并可用于现有对话扣费。
- 只有经服务端确认支付成功的充值才能加分。返回成功页面本身不能作为到账依据；同一笔成功支付不得重复加分。参见 [Stripe Checkout 支付完成说明](https://docs.stripe.com/payments/existing-customers?platform=web&ui=stripe-hosted)。

## 5. 用户操作流程

登录用户点击“充值” → 选择币种并输入金额 → 查看可得积分和应付金额 → 点击“支付”进入 Stripe 沙盒页面 → 使用测试支付方式完成支付 → 返回项目并查看充值结果及更新后的积分余额。用户取消支付或支付失败时，余额不增加，并能看到相应结果。

## 6. 预期实现效果

用户能完成一次没有真实资金流动的测试充值；成功支付所获积分进入当前账号余额，并按既有规则消耗。

## 7. 功能边界与约束

- 本次仅使用 Stripe 沙盒，不启用真实收款。
- 支付金额只接受正整数；积分也只增加整数。
- 可选币种以 Stripe 沙盒账户在该支付流程中实际可用的币种为准。
- 本次需求不包含真实支付上线、汇率换算或人工补分。

## 8. 异常情况与边界处理

- 金额为空、非整数、非正数或不满足所选币种的支付限制时，不允许继续支付。
- Stripe 支付失败、取消或尚未确认成功时，不增加积分。
- 支付成功后即使用户未返回项目页面，积分仍应到账；重复收到同一支付结果也只能到账一次。
- 充值结果暂时无法确认时，应显示待确认状态，不能提前显示为成功。

## 9. 验收标准

- [ ] 已登录用户可从积分旁打开充值界面；未登录用户看不到该入口。
- [ ] 选择可用币种并输入整数 `10` 时，界面显示获得 `10` 积分及该币种的应付金额 `10`。
- [ ] 有效金额可进入 Stripe 沙盒支付页面。
- [ ] 使用 Stripe 官方成功测试卡完成支付后，当前账号增加相应积分，刷新后仍保留；同一笔支付不会重复增加。
- [ ] 取消、失败和无效金额均不会增加积分。
- [ ] 新增积分可用于现有对话扣费。

## 10. 已确认事项与合理假设

- **已确认：**本需求为充值；可选多种 Stripe 支持的币种，金额数字与积分一比一；只接受正整数；沙盒支付成功后积分实际可用。
- **合理假设：**“Stripe 支持的多种币种”指当前沙盒账户及本次支付流程实际可用的币种；具体可选范围需要在后续设计阶段核对账户能力。

Stripe 官方的[测试卡文档](https://docs.stripe.com/testing)给出了成功支付卡号 `4242 4242 4242 4242`：使用未来有效期和任意三位 CVC 即可测试，也提供拒付场景卡号。
