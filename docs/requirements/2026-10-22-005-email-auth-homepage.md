# 邮箱账号注册与登录及主页面

## 1. 需求背景

项目目前没有面向用户的注册或登录流程。开发环境使用固定主体 `local-development`，会话、文献和简历等数据按可信主体归属。需要增加邮箱账号能力，并在用户进入应用前提供一个介绍智能体、承载登录注册入口的主页面。

## 2. 需求目标

用户打开项目后先看到新的主页面：左侧展示项目智能体及图标，右侧提供登录和注册入口。用户可以通过邮箱验证码完成注册，之后使用邮箱和密码登录；忘记密码时，可以通过邮箱验证码设置新密码。

## 3. 当前功能现状

前端入口直接展示聊天页面，或根据地址展示简历页面，没有登录界面。聊天区域已有智能体目录展示组件；智能体头像按类型绘制。后端在开发环境缺少认证中间件时使用固定主体 `local-development`；生产环境缺少身份凭证时返回 401。数据库已有唯一账号字段和可空密码哈希字段，但项目中未发现注册、邮箱登录或验证码流程。

项目依据：`frontend/src/App.tsx`、`frontend/src/features/chat/components/AgentDirectory.tsx`、`frontend/src/features/chat/components/AgentAvatar.tsx`、`backend/app/dependencies/auth.py`、`backend/app/models/user.py`。

## 4. 详细功能需求

### 4.1 主页面

- 用户打开项目时，未登录状态展示新的主页面。
- 页面左侧展示项目当前可用的智能体及各自图标。
- 页面右侧展示登录和注册入口。
- 用户完成登录后进入现有应用。

### 4.2 注册

- 用户输入邮箱并申请邮箱验证码。
- 用户提交邮箱、验证码、密码及密码确认完成注册。
- 注册成功后，邮箱成为该用户的登录账号。
- 已注册邮箱不能重复注册。

### 4.3 登录

- 用户输入邮箱和密码登录。
- 登录成功后进入应用。
- 邮箱不存在或密码错误时，提示登录未成功，不泄露不必要的账号信息。

### 4.4 找回密码

- 用户在登录界面选择“忘记密码”，输入邮箱并申请验证码。
- 用户提交邮箱、验证码、新密码及确认密码。
- 验证成功且两次输入的新密码一致后，更新密码。
- 找回密码不创建新账号；未注册邮箱不能通过此流程设置密码。

### 4.5 登录状态

- 未登录用户不能进入聊天和简历页面；登录后可访问这些页面。
- 用户可以主动退出登录。退出后返回未登录状态。

## 5. 用户操作流程

- **首次访问：**打开项目 → 查看左侧智能体及图标 → 在右侧选择登录或注册。
- **注册：**输入邮箱并获取验证码 → 输入验证码和密码、确认密码 → 注册成功并进入应用。
- **登录：**输入邮箱和密码 → 登录成功并进入应用。
- **找回密码：**选择忘记密码 → 输入邮箱并获取验证码 → 输入验证码、新密码并确认 → 更新成功后返回登录。
- **退出：**在已登录状态选择退出 → 返回未登录状态，重新显示主页面。

## 6. 预期实现效果

未登录用户能在同一页面浏览项目智能体并使用登录注册入口。登录后进入聊天和简历功能。不同邮箱账号对应各自的数据归属；当前固定开发身份下产生的数据不会自动关联到新注册的邮箱账号。

## 7. 功能边界与约束

- 第一版包含主页面、邮箱注册、邮箱＋密码登录、邮箱验证码找回密码及退出登录。
- 登录不使用邮箱验证码；验证码仅用于注册和找回密码。
- 主页面展示当前项目可用的智能体；不预设固定智能体名单。
- 新邮箱账号从独立数据开始，不迁移或关联固定开发身份的数据。
- 未提出第三方账号登录、手机号登录或管理员账号管理需求，本次不纳入范围。

## 8. 异常情况与边界处理

- 邮箱格式无效、验证码错误或失效、邮箱已注册、密码不匹配时，应提示用户并阻止相应操作。
- 登录凭证无效时，不进入应用。
- 未登录用户访问聊天或简历页面时，应转到主页面。
- 项目当前未发现邮件发送能力；验证码邮件的实际发送条件和配置方式需在后续设计阶段核实。

## 9. 验收标准

- [ ] 未登录用户打开项目时看到主页面，左侧展示当前可用智能体及图标，右侧展示登录注册入口。
- [ ] 新邮箱可通过邮箱验证码和密码完成注册。
- [ ] 已注册邮箱可使用正确密码登录；错误凭证不能登录。
- [ ] 已注册用户可通过邮箱验证码设置并确认新密码，之后可用新密码登录。
- [ ] 未注册邮箱不能通过找回密码流程创建账号或设置密码。
- [ ] 未登录用户无法访问聊天和简历页面；登录后可以访问。
- [ ] 用户退出后回到未登录主页面。
- [ ] 新注册邮箱账号的数据与固定开发身份下的现有数据相互独立。

## 10. 已确认事项与合理假设

- **已确认：**注册和找回密码使用邮箱验证码；日常登录使用邮箱＋密码；找回密码后设置新密码；新邮箱账号不关联固定开发身份下的数据；主页面左侧展示智能体和图标，右侧提供登录注册入口。
- **合理假设：**登录保护整个应用，包括聊天和简历页面；注册时确认密码；提供主动退出功能。登录后进入现有应用。
- **待后续核实：**项目尚未发现邮件发送能力；具体发送方式和运行配置留待后续设计阶段核实。
