# 用户积分计费

## 1. 需求背景

NexusAI 已支持邮箱注册和多智能体对话，但当前没有用户积分、消息计费和余额展示。用户希望先以积分作为计费单位：新用户获得初始积分，发起对话消耗积分，运行失败或取消时退回积分。

## 2. 需求目标

每个用户拥有独立的积分余额。系统在用户发起新的智能体对话时按轮次扣费，在失败或主动取消时退款，并在账号区域展示余额。积分变动应可追溯，项目启动后应能从 Redis 快速读取用户积分。

## 3. 当前功能现状

- 邮箱注册会创建 `users` 账号；当前用户模型和数据库文档没有积分余额或积分明细。依据：`backend/app/service/auth.py`、`backend/app/models/user.py`、`docs/数据库文档.md`。
- 顶部账号栏目前显示邮箱和退出登录，没有积分。依据：`frontend/src/App.tsx`。
- 普通智能体对话和文献问答分别有提交入口；智能体追问后的答案会恢复同一次运行。依据：`backend/app/router/agents.py`、`backend/app/router/literature.py`、`backend/app/service/agent.py`。
- 智能体运行已有 `completed`、`waiting`、`failed`、`cancelled` 等状态；Redis 已用于队列、事件和认证状态。依据：`backend/agent/schemas/run.py`、`docs/接口文档.md`、`docs/项目知识地图.md`。

## 4. 详细功能需求

### 4.1 账号积分与记录

- 新账号注册成功后获得 100 积分，仅赠送一次。
- 功能上线前已存在的用户不补发积分，初始余额为 0。
- 新增两张独立的数据表：**积分表**保存用户积分，**积分明细表**记录积分的赠送、扣除和退回，使余额变动可追溯。具体字段、约束、索引和表间关系在下一阶段设计，本需求文档不定义数据库表结构。
- 积分按已认证用户归属，不能跨用户共享；余额不能为负数。

### 4.2 对话计费

- 所有智能体的对话均适用同一计费规则，包括普通对话、文献问答、图片生成、Listing 和求职助手等现有智能体。
- 用户每发起一轮新的对话消息，系统先检查积分；余额至少为 1 时受理消息并扣除 1 积分。余额为 0 时不受理该消息，并提示积分不足。
- 智能体回复不扣积分。智能体追问后，用户提交题卡答案或同轮补充信息，属于原对话轮次，不再次扣费；用户另行发起的新一轮对话仍按 1 积分计费。
- 同一发送请求因网络重试或重复提交而被重复处理时，不得重复扣费。

### 4.3 退款与余额展示

- 已扣费的对话轮次若以系统运行失败状态结束，或用户主动取消生成，退回该轮扣除的 1 积分；同一轮次不得重复退款。
- 浏览器断线但后台仍继续运行，不视为取消；后续按该轮次实际运行结果决定是否退款。
- 登录后在顶部账号邮箱左侧显示当前用户的积分余额；扣费或退款后，显示值应更新。

### 4.4 Redis 缓存

- 每次项目启动时，将用户积分加载到 Redis，供发送消息前的频繁积分查询使用。
- 注册赠送、消息扣费、失败退款及项目重启后，用户看到的余额应与实际积分变动一致，不因缓存重建重复赠送、扣费或退款。

## 5. 用户操作流程

1. 用户注册成功后获得 100 积分，登录进入应用时在账号左侧看到余额。
2. 用户向任一智能体发送新一轮对话消息；系统先检查余额。积分足够时受理消息并扣 1 分，积分不足时拒绝并提示。
3. 智能体正常完成回复后，保留本轮扣费。若智能体追问，用户在同一轮提交答案不再次扣费。
4. 若本轮系统运行失败或用户主动取消，系统退回本轮扣除的 1 分，并更新显示余额。

## 6. 预期实现效果

用户可以持续看到自己的积分余额；一轮成功受理并完成的对话消耗 1 分，同轮追问不增加费用；失败或主动取消的轮次最终不消耗积分。每次积分变动可在明细中追溯。

## 7. 功能边界与约束

- 本期不提供充值或人工补分功能。现有用户从 0 分开始，因此上线后暂时无法发送收费对话消息。
- 浏览智能体、读取会话历史、上传附件等非对话消息操作不计费。
- 本阶段只确认需要积分表和积分明细表，不确定其字段、主键、索引、事务方式或 Redis 键设计；这些属于下一阶段的数据库及技术设计。

## 8. 异常情况与边界处理

- 余额不足时不受理新对话消息，余额不得变为负数。
- 重复发送请求不得重复扣费；重复失败或取消处理不得重复退款。
- **合理假设：**“智能体回复失败”以系统记录的运行失败状态为准。智能体正常结束但回答“不知道”或拒答，不属于系统运行失败。
- **合理假设：**暂时无法可靠核验积分时，不受理新对话消息，并提示用户稍后重试。

## 9. 验收标准

- [ ] 新账号注册成功后显示 100 积分，重复注册不再获赠；现有账号上线时显示 0 积分。
- [ ] 积分表能表示每个用户的余额，积分明细表能追溯注册赠送、消息扣费和失败或取消退款；具体结构按下一阶段设计验收。
- [ ] 任一智能体受理一条新轮次用户对话消息后，该用户余额减少 1；其他用户余额不受影响。
- [ ] 0 积分时无法发起新的收费对话，并收到明确的积分不足提示。
- [ ] 智能体回复以及同轮追问答案提交不额外扣费。
- [ ] 运行失败或主动取消后退回本轮积分；浏览器断线但后台继续运行时不立即退款。
- [ ] 网络重试、重复请求或重复终态处理不会造成重复扣费、重复退款。
- [ ] 顶部账号邮箱左侧显示余额；扣费、退款、刷新页面和项目重启后，显示余额与实际积分结果一致。

## 10. 已确认事项与合理假设

- **已确认：**新注册用户赠送 100 积分；现有用户不补发、从 0 分开始；所有智能体对话按新轮次扣 1 积分；智能体回复和同轮追问答案不扣费；系统失败及主动取消均退款；余额显示在账号左侧；每次启动加载积分到 Redis；本期无充值或人工补分；新增积分表与积分明细表，具体数据库设计留到下一阶段。
- **合理假设：**系统运行失败以已有的 `failed` 运行状态为准；积分暂时无法可靠核验时阻止发送并提示稍后重试。
