# 数据库表结构（初期）

## 设计范围

初期只设计产品需要直接查询的三张表：会话、消息、Agent 运行。会话表保存归属和列表信息，消息表保存用户可见的对话内容，运行表支持当前已有的暂停、恢复和取消能力。

LangGraph Checkpointer 使用的内部表由框架自动创建和迁移，不在本文重复设计。用户认证由外部请求上下文提供，当前不新增用户表。

## 1. `conversations` 会话表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `conversation_id` | `TEXT` | 主键 | 会话标识；与现有 API 字符串 ID 兼容 |
| `owner_id` | `TEXT` | 非空 | 会话所属可信主体 |
| `title` | `TEXT` | 可空 | 会话标题；初期可由首条用户消息生成 |
| `created_at` | `TIMESTAMPTZ` | 非空，默认当前时间 | 创建时间 |
| `updated_at` | `TIMESTAMPTZ` | 非空，默认当前时间 | 最近更新时间，用于会话列表排序 |

索引：`(owner_id, updated_at DESC)`，用于查询某个主体最近更新的会话。

## 2. `messages` 消息表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `message_id` | `TEXT` | 主键 | 消息标识 |
| `conversation_id` | `TEXT` | 非空，外键 | 关联 `conversations.conversation_id`，删除会话时级联删除 |
| `run_id` | `TEXT` | 可空，外键 | 关联产生该消息的 Agent 运行；用户消息可关联本轮运行 |
| `sequence` | `BIGINT` | 非空 | 消息在会话内的顺序 |
| `role` | `TEXT` | 非空，仅允许 `user`、`assistant` | 消息角色 |
| `content` | `TEXT` | 非空 | 消息正文 |
| `created_at` | `TIMESTAMPTZ` | 非空，默认当前时间 | 创建时间 |

唯一约束：`(conversation_id, sequence)`，保证同一会话内顺序不重复。查询历史时按 `sequence` 升序，并按 `conversation_id` 分页。

初期只保存用户消息和助手最终回复；SSE token 增量、心跳等传输事件不写入消息表。

## 3. `agent_runs` Agent 运行表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `run_id` | `TEXT` | 主键 | 一次 Agent 运行的标识 |
| `conversation_id` | `TEXT` | 非空，外键 | 关联所属会话 |
| `status` | `TEXT` | 非空 | `running`、`waiting`、`completed`、`cancelled` 或 `failed` |
| `metadata` | `JSONB` | 非空，默认空对象 | 保存恢复所需的待答问题标识等运行数据 |
| `created_at` | `TIMESTAMPTZ` | 非空，默认当前时间 | 运行创建时间 |
| `updated_at` | `TIMESTAMPTZ` | 非空，默认当前时间 | 最近状态变更时间 |

索引：`(conversation_id, created_at DESC)`，用于查询会话中的运行记录。主体归属通过关联会话的 `owner_id` 校验，避免重复保存所有者字段。

## 框架内部存储

LangGraph PostgreSQL Checkpointer 当前管理 `checkpoint_migrations`、`checkpoints`、`checkpoint_blobs`、`checkpoint_writes`，用于图状态和中断恢复。它们不是消息历史，不要手工改表结构或与 `messages` 合并。

SSE 事件历史和游标表不属于初期会话/消息模型。当前 SSE 直接实时传输事件，不提供断线续传，因此不建立事件历史表；后续确需断线续传时再单独增加。
