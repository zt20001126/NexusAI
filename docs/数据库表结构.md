# 数据库结构说明

本文记录应用直接管理的 PostgreSQL 表。运行时模型定义位于 `backend/app/models/`，由 `backend/app/db/database.py` 初始化；已有数据库的升级脚本位于 `backend/migrations/`。LangGraph Checkpointer 的内部表由官方适配器管理。

## ID 约定

- 应用业务表中的主键和关联 ID 使用 PostgreSQL `BIGINT` 保存雪花 ID。
- API 将雪花 ID 作为十进制字符串传输，避免 JavaScript `Number` 精度损失。
- API 的 `agent_id` 使用 `common_agent`、`basic_conversation_agent`、`image_agent`、`listing_agent` 等稳定代码；数据库存储对应的静态雪花 ID。代码统一命名后，既有雪花 ID 数值保持不变，无需数据迁移。
- 当前认证上下文提供的是外部主体字符串。`user_identities` 将其映射到内部雪花用户 ID，外部主体字符串不会作为业务表的 ID 列保存。
- `SNOWFLAKE_WORKER_ID` 必须在同时运行的后端进程间唯一，允许范围为 0–1021；1022 为静态智能体 ID 保留，1023 为历史数据迁移保留。

## 表及关系

| 表 | 用途 | 主要关系 |
|---|---|---|
| `user_identities` | 外部认证主体到内部雪花用户 ID 的映射 | 一个主体对应一个内部用户 ID |
| `conversations` | 会话归属、标题、智能体和时间 | 一个会话包含多条消息和多次运行 |
| `messages` | 用户消息和助手回复 | 属于一个会话，可关联运行 |
| `agent_runs` | 智能体运行状态和恢复元数据 | 属于一个会话 |
| `task_results` | 所有智能体共享的任务结果及 JSON 元数据 | 关联智能体、用户、会话、运行和可选消息 |
| `literature_documents` | 文献来源、OSS 对象及导入状态 | 关联文献所有者 |
| `literature_chunks` | 文献正文、位置和 1024 维向量 | 关联文献并级联删除 |
| `literature_conversation_documents` | 文献助手会话的当前文献选择 | 关联会话和文献 |

参考图、生成图和 PDF 原件只存放在私有阿里云 OSS Bucket 中，不把文件字节写入 PostgreSQL。图片 OSS 元数据按用途保存在 `task_results.input_data` 和 `task_results.result_data` JSONB 中；文献对象键保存在 `literature_documents.object_key`。

## `user_identities`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `user_id` | `BIGINT` | 主键 | 内部雪花用户 ID |
| `external_principal` | `TEXT` | 非空、唯一 | 认证依赖提供的可信主体标识 |
| `created_at` | `TIMESTAMPTZ` | 非空 | 映射创建时间 |

`external_principal` 是认证映射值，不是业务表主键。未来接入正式用户系统后，可在身份层将映射切换到用户中心的数值 ID。

## `conversations`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `conversation_id` | `BIGINT` | 主键 | 会话雪花 ID |
| `owner_id` | `BIGINT` | 非空，外键 | 关联 `user_identities.user_id` |
| `agent_id` | `BIGINT` | 非空 | 静态智能体雪花 ID |
| `title` | `TEXT` | 可空 | 根据首条用户消息生成的会话标题 |
| `created_at`、`updated_at` | `TIMESTAMPTZ` | 非空 | 创建及最近更新时间 |

索引：`(owner_id, updated_at DESC)`。

## `messages`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `message_id` | `BIGINT` | 主键 | 消息雪花 ID |
| `conversation_id` | `BIGINT` | 非空，外键 | 所属会话，删除会话时级联删除 |
| `run_id` | `BIGINT` | 可空，外键 | 产生消息的运行；运行删除后置空 |
| `sequence` | `BIGINT` | 非空 | 会话内消息顺序，与会话 ID 组成唯一约束 |
| `role` | `TEXT` | 非空，仅 `user`、`assistant` | 消息角色 |
| `content` | `TEXT` | 非空 | 消息正文 |
| `created_at` | `TIMESTAMPTZ` | 非空 | 创建时间 |

唯一约束 `(conversation_id, sequence)` 同时支持按会话和顺序查询。SSE 增量、心跳和工具内部消息不作为消息记录保存。

## `agent_runs`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `run_id` | `BIGINT` | 主键 | 一次运行的雪花 ID |
| `conversation_id` | `BIGINT` | 非空，外键 | 所属会话 |
| `agent_id` | `BIGINT` | 非空 | 执行运行的智能体雪花 ID |
| `status` | `TEXT` | 非空 | `running`、`waiting`、`completed`、`cancelled` 或 `failed` |
| `metadata` | `JSONB` | 非空，默认空对象 | 结果 ID、附件 ID、待回答问题等恢复元数据 |
| `created_at`、`updated_at` | `TIMESTAMPTZ` | 非空 | 创建及最近更新时间 |

索引：`(conversation_id)`。恢复运行时还会校验会话、用户、状态和智能体归属。

## `task_results`

这是所有智能体共用的任务结果表。新增业务专属结果时优先扩展 JSON 元数据，不新建只存输出文件的表。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `task_result_id` | `BIGINT` | 主键 | 任务结果雪花 ID |
| `agent_id` | `BIGINT` | 非空 | 产生结果的智能体雪花 ID |
| `user_id` | `BIGINT` | 非空，外键 | 关联 `user_identities.user_id` |
| `conversation_id` | `BIGINT` | 非空，外键 | 所属会话 |
| `run_id` | `BIGINT` | 非空，外键 | 所属智能体运行 |
| `message_id` | `BIGINT` | 可空，外键 | 关联助手问题或最终回复消息 |
| `result_type` | `TEXT` | 非空 | 结果类型，当前包含图片任务 `image` 和 Listing 文案任务 `listing` |
| `generation_status` | `TEXT` | 非空 | `pending`、`awaiting_input`、`running`、`succeeded`、`failed` 或 `cancelled` |
| `input_data` | `JSONB` | 非空，默认空对象 | 业务输入摘要及所需对象元数据 |
| `result_data` | `JSONB` | 非空，默认空对象 | 图片 OSS 元数据或完整 Listing 生成 JSON |
| `created_at`、`updated_at` | `TIMESTAMPTZ` | 非空 | 创建及最近更新时间 |

表中不再有 `image_url`、`image_data`、`input_files`、`result_files` 或 `error_data` 等独立列。图片不保存在数据库字节字段中；JSON 里的对象键指向私有 OSS，图片读取接口会校验结果所有者后从 OSS 读取。失败原因仅通过安全的 API/SSE 响应返回，不作为任务结果错误字段持久化。

索引：`(user_id, created_at DESC)`、`(conversation_id, created_at)`、`(run_id)`、`(agent_id, created_at)`、`(message_id)`。

result_type 当前包含 image（图片任务）和 listing（淘宝文案任务）。result_data 对图片任务保存 OSS 结果元数据；对 Listing 任务保存经 Schema 校验的完整业务 JSON。

## 文献解读助手表

`literature_documents` 保存文献所有者、私有 OSS 对象键、文件摘要和导入状态。新建文献只通过 PDF 上传，因此 `source_type` 为 `pdf_upload`。`source_url` 和 `pdf_url`/`web_url` 来源类型仅为兼容既有链接导入记录保留；新接口不再创建此类记录。状态为 `queued`、`processing`、`ready` 或 `failed`；只有 `ready` 文献可被问答检索。

`literature_chunks` 保存解析后的原文分块、章节和节标题、PDF 页码范围、页内段落范围以及 `VECTOR(1024)` 向量。`(document_id, chunk_index)` 唯一；对文献 ID 和向量余弦距离建检索索引。既有网页来源文献可能没有页码和段落；新上传 PDF 按解析结果生成可用位置。

`literature_conversation_documents` 用 `(conversation_id, document_id)` 保存会话当前选择。所有查询都通过会话所有者、文献所有者和文献 ready 状态校验；删除文献时级联清理分块与会话选择，历史消息本身仍保留。

升级已有数据库时执行 `backend/migrations/005_literature_reader.sql`。该迁移要求 PostgreSQL 已安装 pgvector；Compose 使用的 `pgvector/pgvector:pg17` 镜像包含该扩展。

### Listing 任务结果

Listing Agent 不增加专用表或迁移脚本。成功任务将 schema_version、商品事实、视觉识别结果和 3 个版本的标题、卖点、纯文本详情描述、关键词及商品属性完整写入 task_results.result_data JSONB；任务输入摘要保存在 input_data。视觉分析所需图片从私有 OSS 读取，图片字节不会写进 PostgreSQL。结果读取 API 使用既有任务所有者校验。

## OSS 对象组织

Bucket 应设置为私有。代码将文件存放在 `ALIYUN_OSS_OBJECT_PREFIX` 下的 `staged/`、`references/`、`generated/` 和 `literature/<主体摘要>/<文献 ID>.pdf` 前缀，并将用户主体摘要写入对象路径与 OSS 元数据，避免把认证主体原文放入对象键。生成图片通过 `/api/task-results/{task_result_id}/image` 返回，不向前端暴露 OSS 公共地址或 TokenHub 临时地址。

所需配置为 `ALIYUN_OSS_ACCESS_KEY_ID`、`ALIYUN_OSS_ACCESS_KEY_SECRET`、`ALIYUN_OSS_ENDPOINT`、`ALIYUN_OSS_BUCKET` 和可选的 `ALIYUN_OSS_OBJECT_PREFIX`。访问密钥应使用 RAM 用户并限制到目标 Bucket 所需的读写权限；不要把密钥提交到 Git。

## 从 TEXT ID 和 BYTEA 图片升级

`003_snowflake_ids_oss_task_results.sql` 是一次性迁移。它要求先停止运行中的任务，并且所有旧图片字节已转存 OSS。建议按以下顺序执行：

1. 备份 PostgreSQL 数据库，并确认 OSS Bucket 为私有且后端已配置有效密钥。
2. 在 `backend/` 目录运行 `python -m migrations.migrate_media_to_oss`。脚本把旧 `task_results.image_data` 和 `message_attachments.image_data` 写入 OSS；只有每项写入成功后，才在数据库事务中清空/删除旧字节。
3. 确认脚本成功后，在旧数据库执行 `migrations/003_snowflake_ids_oss_task_results.sql`。
4. 部署当前后端，并为每个并发后端进程设置唯一的 `SNOWFLAKE_WORKER_ID`。

SQL 会把会话、消息、运行、用户和任务结果 ID 迁移到雪花 BIGINT，保留关联和兼容的 Checkpoint 线程标识，移除旧附件表及图片字节列。若旧数据的所有者或智能体关系不一致，迁移会中止并报告，不会猜测修复。此迁移只用于旧 TEXT/ BYTEA schema；空白数据库由当前版本的运行时建表代码直接创建目标结构，不应对它运行 003。

LangGraph Checkpointer 自有的内部 ID/键继续按框架类型保存，不属于应用业务表 ID。
