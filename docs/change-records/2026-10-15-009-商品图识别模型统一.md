# Listing 图片识别复用 DeepSeek 模型

- 日期：2026-10-15
- 变更类型：架构
- 影响范围：Listing 图片理解、模型配置、后端测试和相关项目文档

## 背景

项目已配置 DeepSeek ChatModel，默认模型为 `deepseek-flash`。Listing 图片识别此前另行调用 TokenHub `hy-vision-2.0-instruct`，产生了独立客户端和模型配置。

## 变更内容

- Listing 视觉节点改为复用已注入的 DeepSeek ChatModel，以多模态用户消息发送 Base64 `image_url` 图片内容块。
- 图片识别、必要信息规划和文案生成现在使用同一模型 Provider；恢复运行仍复用已保存的图片分析结果。
- 保留图片 MIME、数量、单张字节数和总字节数校验，并继续校验识图 JSON Schema。
- 删除 TokenHub 视觉客户端及 `TENCENT_TOKENHUB_VISION_MODEL` 配置，从示例环境文件和本地环境文件移除旧模型设置；TokenHub 生图配置继续保留。
- 更新 README、架构/API 文档、Listing PRD/TDD/TODO 和项目变更日志。

## 涉及文件

- `backend/agents/listing_agent/nodes/vision.py`、`backend/agents/listing_agent/graph.py`：复用 DeepSeek ChatModel 进行图片识别。
- `backend/agents/listing_agent/providers/tokenhub_vision.py`：删除独立视觉客户端。
- `backend/bootstrap/runtime.py`、`backend/infra/settings.py`、`backend/.env.example`：移除独立视觉客户端装配和模型配置。
- `backend/tests/test_listing_agent.py`、`backend/tests/test_api.py`：验证图片消息结构和 Listing 流程。
- `README.md`、`docs/架构说明.md`、`docs/接口说明.md`、`docs/agents/listing/`：同步现行模型职责。
- `CHANGELOG.md`：记录 `[Unreleased]` 中的模型调整。
- `backend/.env`：移除不再使用的 `TENCENT_TOKENHUB_VISION_MODEL` 配置项。

## 设计决策

- 视觉节点通过项目现有 `OpenAICompatibleProvider` 创建的 ChatModel 调用 DeepSeek；图片作为 Chat Completions 多模态用户消息的一部分提交。
- TokenHub 仍服务于图片智能体的图片生成，不再承载 Listing 图片识别。

## 潜在影响

- Listing 图片识别会计入现有 DeepSeek API 用量，并受 `DEEPSEEK_TIMEOUT_SECONDS` 与 DeepSeek 多模态 API 限制约束。
- 部署环境中的 `TENCENT_TOKENHUB_VISION_MODEL` 不再读取；TokenHub API Key 仍由图片智能体生图能力使用。
