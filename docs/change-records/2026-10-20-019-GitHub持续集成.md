# GitHub 持续集成

- 日期：2026-10-20
- 变更类型：工程化
- 影响范围：对 `main`、`dev` 的提交和面向这两个分支的 Pull Request 自动运行前后端验证。

## 背景

仓库之前没有 GitHub Actions workflow，提交与 Pull Request 不会自动运行已有测试和前端生产构建。

## 变更内容

- 新增 GitHub Actions CI，后端测试与前端测试/构建并行执行，仅授予 workflow 仓库内容只读权限，不使用生产密钥。
- 为流式运行时测试假模型增加显式异步握手，避免模型完成标志与首个增量事件消费之间的线程调度竞争。
- 在项目 `[Unreleased]` 更新中记录 CI 能力。

## 涉及文件

- `.github/workflows/ci.yml`：新增 `main`、`dev` push/PR 触发规则、并发取消、Python 3.12.13 与 Node 22 环境，以及后端和前端两个 job。
- `backend/tests/test_runtime.py`：确定性地控制假模型分块时序，保持验证首个增量在模型完成前到达的原意。
- `CHANGELOG.md`：新增 GitHub Actions CI 摘要。
- `docs/implementation-plans/2026-10-20-018-GitHub持续集成方案.md`：记录实际实施范围、验证结果和首次 GitHub 运行待办。
- `docs/change-records/2026-10-20-019-GitHub持续集成.md`：本任务记录。

## 设计决策

- workflow 直接复用现有 pytest、npm scripts 和已跟踪的 `frontend/package-lock.json`；不增设部署、镜像构建、外部服务容器或密钥配置。
- CI job 使用 `contents: read`，并在同一分支有新运行时取消旧运行。
- 初次完整后端测试曾出现一次流式时序断言失败。根因是测试假模型同步且无等待地发出两段内容，测试观察时序受调度影响；以测试握手稳定假模型，不改变生产 Runner。
- 分支保护为 GitHub 仓库外部设置，未在本次代码改动中配置。首次 GitHub Actions 运行需确认 hosted runner 可访问锁文件中的 `registry.npmmirror.com` 地址。

## 测试与验证

- 命令：在隔离的 Python 3.12.13 虚拟环境安装 `backend/requirements.txt` 后运行 `python -m pytest -q`。
- 结果：138 项通过，1 条 Starlette/AnyIO 弃用警告。
- 命令：连续运行 `tests/test_runtime.py::test_basic_conversation_forwards_model_chunks_before_completion` 10 次。
- 结果：10 次全部通过。
- 命令：在排除项目现有 `node_modules` 的临时前端源码副本中运行 `npm ci`、`npm test`、`npm run build`。
- 结果：安装成功，13 项前端测试通过，生产构建成功；Vite 提示部分 bundle chunk 超过 500 kB。
- 命令：使用 PyYAML 解析 workflow，并断言触发分支、只读权限和两个 job。
- 结果：通过。`actionlint` 未安装，未运行；GitHub Actions 尚未在远端触发，因为本次没有推送或创建 PR。
- 补充：全局 Python 3.11.5 环境直接运行 pytest 时因依赖缺失/版本不符而无法收集测试，随后改用项目要求的隔离 Python 3.12.13 环境完成验证。原工作区 `npm ci` 因开发服务器占用 Rolldown 文件收到 EPERM；随后 `npm install --no-audit --no-fund` 以退出码 0 恢复依赖目录，`frontend/package-lock.json` 无差异。
- 命令：`git diff --check`。
- 结果：跟踪文件差异通过；新增文件另行检查未发现行尾空格。

## 潜在影响

- 前端锁文件当前引用 `registry.npmmirror.com`；本地临时副本安装成功，但 GitHub hosted runner 的网络可达性尚未验证。
- 前端构建成功但有 bundle chunk 体积警告；该提示不影响本次构建退出状态。

## 后续事项

- 用户审核并自行提交后，由面向 `main` 或 `dev` 的 Pull Request 触发真实 GitHub Actions 检查。
- 如需失败检查阻止合并，在 GitHub 仓库分支规则中把 `CI / Backend Tests` 与 `CI / Frontend Checks` 设为必需检查。
