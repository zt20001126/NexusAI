# 用户积分计费实现

- 日期：2026-10-23
- 变更类型：新功能、接口与数据模型
- 影响范围：邮箱注册、所有智能体对话入口、积分持久化与 Redis 缓存、聊天账号栏

## 背景

按已确认的用户积分计费需求，为新注册用户赠送 100 分；所有智能体每轮新对话扣 1 分；追问答案免费；失败或主动取消退款；现有用户上线时余额为 0。所有对话提交入口要求稳定 `request_id`，以避免重试重复扣费。

## 变更内容

- 增加 `user_credits` 和 `credit_entries` 两张表及 `018_user_credits.sql`；迁移为现有用户补建 0 分余额，新注册赠分与账号创建在同一事务内提交。
- 增加统一的积分服务、Redis 版本缓存和事务型对话受理：用户消息、queued run、余额扣减及扣费明细原子写入；余额不足不保存新消息或运行。
- 普通对话、文献问答、科研 REST 和追问恢复要求 `request_id`；对话入口保持同键同输入幂等，追问恢复不重复扣费。
- Agent Worker 在失败或取消后幂等退款；启动恢复对失败/取消但未退款的运行补偿；SSE 断线不会退款。
- API lifespan 分页对账并预热 Redis；Worker 重建运行时跳过全量预热。账号会话返回积分余额，前端在邮箱左侧展示并在提交、终态和积分不足后刷新。
- 同步接口、架构、数据库、启动文档和 `CHANGELOG.md`；更新实施方案记录实际状态。

## 设计决策

- PostgreSQL 余额是账务事实来源；Redis 缓存余额与单调版本，版本比较避免启动快照或并发发布覆盖较新值。
- 仅计费的新消息采用一个数据库事务写入消息、运行和扣费；已有 request key 通过数据库约束及事务查询复用。
- 余额不足返回受控 `INSUFFICIENT_CREDITS`（HTTP 402）；缓存不可用时拒绝新提交（HTTP 503）。
- Worker 不在每个任务中全量预热 Redis；API 进程启动时分页核对并预热。

## 潜在影响

- `request_id` 从可选改为必填，已有直接 API 调用方需同时升级，并在网络重试时复用首次生成的 ID。
- 迁移必须在新版 API 和 Worker 启动前应用；现有用户不会获得 100 分，当前没有充值或人工补分入口。
