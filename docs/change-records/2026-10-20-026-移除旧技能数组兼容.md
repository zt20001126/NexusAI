# 移除旧技能数组兼容

- 日期：2026-10-20
- 变更类型：接口与数据模型
- 影响范围：简历技能 API、后端校验和测试

## 背景

当前 Compose 数据库已执行迁移 015，旧版 `string[]` 技能数据已转换为 Tiptap 文档。继续保留运行时转换器会让接口同时接受两种格式，并掩盖其他部署未执行数据库迁移的问题。

## 变更内容

- 移除 `ResumeContent` 的旧技能数组转换器及仅供旧格式校验使用的数量、单项长度常量。
- 更新 API 和服务测试数据为 Tiptap 文档；新增旧数组载荷拒绝校验。
- 更新 API 文档、数据库文档和 `[Unreleased]`，要求已有数据库先执行 015。

## 涉及文件

- `backend/app/schemas/resume.py`：移除旧数组兼容转换。
- `backend/tests/test_resume_api.py`、`backend/tests/test_resume_pdf.py`、`backend/tests/test_resume_service.py`：改用新文档契约并覆盖数组拒绝行为。
- `docs/接口文档.md`、`docs/数据库文档.md`、`CHANGELOG.md`：记录当前格式契约和升级顺序。

## 设计决策

- 所有已有数据库必须先应用 `015_resume_skills_tiptap.sql`，再部署不接受旧数组的 API。
- 当前 Compose 数据库已经回填；数据库迁移本身保持不变。

## 测试与验证

- 命令：`python -m pytest -q tests/test_resume_api.py tests/test_resume_pdf.py tests/test_resume_service.py`（工作目录 `backend/`）
- 结果：27 项通过，1 项 Starlette/AnyIO 弃用警告。
- 命令：`git diff --check`
- 结果：通过；Git 提示工作区 LF 文件后续可能转换为 CRLF。

## 潜在影响

- 尚未迁移的部署在升级 API 前必须执行迁移 015，否则旧技能数组无法通过响应模型校验。
