# 求职智能体基础框架

- 日期：2026-10-21
- 变更类型：新功能
- 影响范围：简历工作台、智能体注册与对话运行

## 背景

简历助手原先仅提供编辑、预览和 PDF 导出。用户希望在左侧目录增加“07 求职助手”，点击后让右侧编辑区切换为对话框，并先建立独立的 `job_agent` 基础代码框架。

## 变更内容

- 将 `base_agent` 的图、节点、状态、Schema、错误、工具和提示词结构复制为独立的 `backend/agents/job_agent/`，调整本地导入和类名。
- 注册稳定的 `job_agent` 类型、目录元数据和运行时 Runner，复用现有 Checkpointer、会话、SSE 与追问协议。
- 增加 016 迁移，扩展已有数据库中的会话智能体类型检查约束。
- 简历工作台增加“07 求职助手”入口；右侧使用现有聊天组件展示求职对话、历史会话和输入框。
- 求职智能体仅根据对话中提供的信息回答，不读取或修改简历，不接入职位检索或投递。

## 涉及文件

- `backend/agents/job_agent/`：独立基础图及提示词。
- `backend/agent/`、`backend/agents/registry.py`、`backend/bootstrap/runtime.py`：类型、注册与组装。
- `frontend/src/features/resume/`、`frontend/src/features/chat/`：入口、右侧对话与类型支持。
- `backend/tests/test_job_agent.py`：图和注册基础验证。
- `backend/migrations/016_job_agent_conversation_type.sql`：允许持久化求职会话。
- `docs/项目知识地图.md`、`docs/接口文档.md`、`CHANGELOG.md`：同步用户可见行为及契约。
- `docs/数据库文档.md`：说明已有数据库的升级顺序。

## 设计决策

- 对话复用现有 Agent API 和聊天组件；业务图在 `job_agent` 目录独立，未复制共享 Runner。
- 求职助手只在简历工作台提供新对话入口，智能体市场不重复显示求职卡片。
- 当前简历接口仍使用固定单人主体；求职对话遵循通用 Agent 身份，尚无跨两者的简历数据读写。

## 潜在影响

- `job_agent` 在后端目录 API 中可见，但前端智能体市场隐藏该入口，统一从简历工作台开启。
- 当前 Compose 数据库已应用 016；其他已有数据库仍需在启用求职会话前执行该迁移。
- 右侧对话目前不能获得简历编辑器中的内容，需要用户在对话中提供相关信息。
