# 修复注册验证码来源校验

- 日期：2026-10-22
- 变更类型：缺陷修复
- 影响范围：开发环境注册验证码请求、QQ SMTP 配置读取

## 背景

前端通过 Vite 将 `/api` 请求代理到后端。浏览器的 `Origin` 指向前端开发服务器，而后端看到的 `Host` 是代理目标，原先的严格比较会错误拒绝验证码请求。

## 变更内容

- Vite 代理转发原始浏览器 `Host`，后端来源校验优先使用代理转发值；未匹配的跨站请求仍返回 403。
- SMTP 设置兼容 `MAIL_SMTP_*` 和常见的 `SMTP_*` 环境变量名，避免现有部署变量被忽略。
- 在认证 API 测试中覆盖代理转发来源及跨站拒绝。

## 涉及文件

- `frontend/vite.config.ts`：代理转发前端原始 Host。
- `backend/app/router/auth.py`：来源校验读取转发 Host。
- `backend/infra/settings.py`：兼容两套 SMTP 配置名。
- `backend/tests/test_auth_api.py`、`backend/tests/test_settings.py`：添加回归覆盖。
- `CHANGELOG.md`：记录用户可见修复。

## 设计决策

- 只信任部署代理提供的 `X-Forwarded-Host`，开发环境由 Vite 代理设置；没有该头时继续比较请求 Host。
- SMTP 环境变量名称兼容，不修改本地私有环境文件。

## 测试与验证

- 命令：后端容器内运行认证 API 和 SMTP 设置定向测试。
- 结果：11 项通过；2 项与缺少数据库 URL 的假设冲突的既有设置测试未运行（Compose 容器始终注入数据库 URL）。
- 命令：前端 `npm test`。
- 结果：15 项通过。
- 命令：前端 `npm run build`。
- 结果：通过；Vite 提示现有大体积拆包。
- 命令：经 `http://localhost:5173` 携带浏览器 `Origin` 请求 `/api/auth/email-codes`，使用未注册邮箱的密码找回用途。
- 结果：返回 200 请求已受理，验证来源已通过且不会实际投递邮件。
- 命令：根目录 `git diff --check`。
- 结果：通过；仅有 Git 的 LF/CRLF 转换提示。
- 命令：浏览器控制台复现首页，并以 `npm run dev -- --force` 重启 Vite。
- 结果：定位到依赖优化缓存返回 `504 Outdated Optimize Dep`，强制重建缓存后首页完整渲染，浏览器控制台无错误。

## 潜在影响

- 生产反向代理需覆盖并转发可信的 `X-Forwarded-Host`；否则后端按直接请求 Host 校验。
- 未执行真实 QQ 邮件投递。
