# 新增后端健康巡检

- 日期：2026-10-19
- 变更类型：新功能
- 影响范围：后端健康状态、PostgreSQL/Redis 探针、Docker Compose 运行状态

## 背景

项目已有 PostgreSQL 和 Redis 容器级健康检查，但后端没有周期性检查自身所用依赖并对外报告就绪状态的能力。

## 变更内容

- 新增后台健康巡检器，应用启动时立即检查 PostgreSQL 和 Redis Broker，之后按配置间隔执行；单项失败或超时不会中止后续巡检。
- 新增进程存活与依赖就绪接口；就绪响应只返回脱敏状态、耗时和稳定错误码。
- 在 FastAPI lifespan 中管理巡检任务和 Redis 客户端，在 Docker Compose 中增加后端容器健康检查。
- 新增健康巡检测试，并更新 API、架构、环境变量示例及项目变更记录。

## 涉及文件

- `backend/app/service/health.py`：巡检调度、状态快照及过期判定。
- `backend/infra/health_probes.py`：PostgreSQL 与 Redis Broker 探针适配器。
- `backend/app/router/health.py`、`backend/app/schemas/health.py`：健康接口与响应 DTO。
- `backend/bootstrap/runtime.py`、`backend/bootstrap/application.py`：lifespan 资源管理及路由注册。
- `backend/infra/settings.py`、`backend/.env.example`、`backend/compose.yaml`：巡检时限和容器探活配置。
- `backend/tests/test_health.py`、`backend/tests/test_settings.py`：健康状态、失败恢复、超时、任务生命周期和配置测试。
- `docs/接口说明.md`、`docs/架构说明.md`、`CHANGELOG.md`：接口、分层和用户可见变更说明。

## 设计决策

- 存活检查只判断 HTTP 进程是否能够响应；就绪检查读取后台缓存的依赖结果，避免每次 HTTP 请求都创建数据库或 Redis 连接。
- 后台探针覆盖 PostgreSQL 和 Redis Broker。模型服务、对象存储及独立的 `literature-worker` 进程不在本次巡检范围。
- Docker Compose 将后端标记为 `unhealthy`，不因此自动重启容器。

## 测试与验证

- 命令：`docker compose --env-file .env.example -f compose.yaml config --quiet`
- 结果：通过。
- 命令：`docker compose --env-file .env.example -f compose.yaml build backend`
- 结果：通过，后端镜像成功构建。
- 命令：在后端 Python 3.12 容器中运行 `pytest -q -p no:cacheprovider tests/test_health.py tests/test_settings.py`
- 结果：10 passed。
- 命令：在后端 Python 3.12 容器中运行完整 `pytest -q -p no:cacheprovider`
- 结果：117 passed，3 failed。失败项为现有 Listing 测试，校验拒绝文本题的 `allow_custom_input`；三个失败单独复跑仍可重现，相关 Listing 文件未被本次修改。
- 本机 Python 为 3.11，而项目要求 Python 3.12.13，因此测试在项目 Docker 镜像中执行。

## 潜在影响

- 每个后端进程会周期性打开 PostgreSQL 和 Redis 探测连接；巡检间隔及单项超时可通过环境变量调整。
- 容器显示为 `unhealthy` 不会自动触发重启，自动恢复仍由部署编排策略决定。
