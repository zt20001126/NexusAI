# 精简智能体事件类型

- 日期：2026-10-20
- 变更类型：工程化 / 接口
- 影响范围：智能体 SSE 事件协议、后端运行器与事件回放、聊天前端

## 背景

共享事件协议分别使用 `tool.started` / `tool.completed` 描述工具阶段，以及 `run.completed` / `run.cancelled` / `run.failed` 描述运行结果。各类事件的差异可以通过同一事件载荷中的状态字段表达。

## 变更内容

- 保留 `heartbeat`，将工具阶段事件合并为 `tool.status`，通过 `status` 区分开始和完成。
- 将运行终态事件合并为 `run.terminal`，通过 `status` 区分完成、取消和失败。
- 为合并后的状态载荷增加 Pydantic 校验，失败终态必须包含错误码和用户可读说明。
- 同步更新 Redis 终态识别、Worker 状态恢复、Research 服务、前端事件处理、接口文档和相关既有测试。
- 不保留旧事件类型的读取兼容。

## 涉及文件

- `backend/agent/streaming/events.py`：精简事件类型并校验状态载荷。
- `backend/agent/streaming/__init__.py`：导出统一状态枚举。
- `backend/agent/runner.py`、`backend/infra/agent_event_store.py`：发布新事件并识别统一终态。
- `backend/app/service/agent.py`、`backend/app/service/agent_tasks.py`、`backend/app/service/research.py`：更新终态判断与 Worker 恢复。
- `frontend/src/features/chat/api/agent.ts`、`frontend/src/features/chat/hooks/useChatSession.ts`、`frontend/src/shared/api/http.ts`：声明并消费合并后的事件协议。
- `backend/tests/`：更新既有事件断言和样例数据。
- `docs/接口文档.md`、`CHANGELOG.md`：同步公共协议说明。

## 设计决策

- 保留 `heartbeat`，因为它用于保持 SSE 连接。
- 工具名称、调用 ID、执行成功状态和安全结果继续保留在 `tool.status` 数据中；运行终态及失败信息继续保留在 `run.terminal` 数据中。
- 按要求不解析旧事件。部署期间仍留在 Redis 中的旧格式事件可能无法回放，待事件 TTL 到期后恢复新流读取。
