# 本地 Celery 工作进程合并

- 日期：2026-10-20
- 变更类型：工程化
- 影响范围：本地 Docker Compose 后台任务执行、启动说明和架构文档

## 背景

本地 Compose 原先分别启动 Agent Worker 和文献 Worker。两类任务使用同一个 Celery 应用及 Redis Broker，开发阶段可以由一个进程消费两个队列以减少常驻进程。

## 变更内容

- 将 Compose 服务合并为一个 `worker`，同时监听 `agents` 与默认 `celery` 队列，并保留 Agent 和文献各自的 Snowflake Worker ID 配置。
- 为启动命令加入 `--remove-orphans`，升级本地 Compose 配置时清理旧的两个 Worker 容器。
- 更新 README、架构文档、接口文档和 Unreleased 变更摘要，说明单并发串行处理及文献任务可能延迟聊天任务。

## 涉及文件

- `README.md`：更新本地和 Docker 启动命令、架构图及运行说明。
- `docs/架构说明.md`、`docs/接口文档.md`：同步队列和 Worker 部署说明。

## 设计决策

- 开发阶段使用单个 `solo` Worker 同时监听两个队列，继续使用独立的 Agent 和文献 Snowflake Worker ID。
- 保留单并发设置以控制本地资源占用；长时间文献任务会阻塞其后的聊天任务。

- 结果：通过，Compose 配置成功展开，包含一个同时监听 `celery` 和 `agents` 队列的 Worker。

## 潜在影响

- 单个 Worker 串行执行任务；文献解析、Embedding 等耗时任务会延迟后续聊天任务。
- 首次使用新服务名启动时，README 命令通过 `--remove-orphans` 清理旧 Worker 容器。
