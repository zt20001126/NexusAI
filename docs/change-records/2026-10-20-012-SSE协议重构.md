# SSE 协议重构

- 日期：2026-10-20
- 变更类型：架构 / 接口 / 工程化
- 影响范围：Agent SSE、后台运行与恢复、聊天历史、消息和任务结果展示

## 背景

原事件协议分别使用多种事件名表达消息、工具状态、追问、任务结果和运行终态；流式增量没有稳定消息身份，Redis 存储正文与回放游标也分开生成。新协议将外发 JSON 收敛为四字段，并明确消息快照、追问阶段终止和断线恢复行为。

## 变更内容

- 将事件统一为 `start`、`message`、`status`、`end`、`heartbeat`；外发 JSON 严格限制为 `event_id`、`event_type`、UTC `timestamp`、`data`，SSE 帧字段与 JSON 对齐。
- `message` 支持 `delta` 和 `snapshot`。增量使用稳定的消息/文本块 ID 和字符偏移；偏移用于历史快照已经包含增量时的重放去重。
- 助手消息在发送首个增量前持久化，增量更新与最终快照共用同一 `message_id`；文本、图片、追问和任务结果块均有稳定 ID。旧历史块由读取接口确定性补充 ID。
- 追问在 Checkpoint 可读后保存待答信息和题卡，随后发送 `end(waiting)`；恢复沿用原 `run_id`，通过 `X-Event-Cursor` 从上一阶段结束游标之后监听。`waiting` 不走完成态清理。
- Redis 使用 v2 事件键，原子分配 Stream ID 并持久化事件载荷；heartbeat 不进入业务事件流，waiting 保留续跑游标元数据，最终状态按 TTL 清理。
- Worker 异常补偿可幂等补齐追问题卡和 `end(waiting)`，并用嵌套 `error` 补齐失败终态。任务结果卡按稳定 `message_id` 更新；追问阶段产生的卡片留在对应题卡消息中。
- 前端按消息和内容块 ID 归并事件，增量按偏移重放，快照替换完整消息；waiting、完成、失败和取消分别处理。同步更新 SSE、接口、数据库和架构文档。
- 验证过程中发现 `get_snowflake_generator()` 与 `get_snowflake_generator(0)` 因缓存键不同会创建两个 worker 0 生成器，可能分配重复 ID。已统一到内部归一化缓存，并增加回归测试；内存消息仓储也拒绝重复消息 ID。

## 设计决策

- 不读取旧 SSE 事件；新旧 Redis 键空间隔离。部署时停止旧 API/Worker 写入并处理旧版 `queued/running` 任务；等待中的运行可依据数据库题卡和 Checkpoint 恢复。旧历史仍可读，不批量改写 JSONB。
- 数据库表结构未变化，不需要 SQL 迁移。新增块 ID 保存在现有 JSONB；旧块 ID 在历史读取投影中生成。
- `message.delta` 增加 `offset`。这是保证数据库历史已经包含片段时仍可安全重放所需的额外字段。

## 潜在影响

- 新版 API、Worker 和前端需协调部署；旧 Redis 事件不会被新版本解析。
- waiting run 的游标元数据会保留到该 run 最终结束，长期未恢复的运行会继续占用轻量 Redis key。
