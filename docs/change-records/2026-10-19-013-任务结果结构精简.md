# 精简任务结果表结构

- 日期：2026-10-19
- 变更类型：架构
- 影响范围：任务结果 ORM、PostgreSQL 持久化、会话历史和结果读取

## 背景

`task_results` 存储了可由会话关联推导的智能体、用户和运行字段，以及重复表达结果状态和 JSON 数据的长字段名。按确定的新结构精简持久化列，不保留旧结果数据兼容。

## 变更内容

- 任务结果表改用 `id`、`status`、`input`、`result` 等简短列名，并删除 `agent_id`、`user_id`、`run_id`、`result_type` 和 `updated_at` 列。
- 任务结果所有者及智能体标识从关联会话读取；结果类型按会话智能体标识推导。
- 新增一次性迁移，删除并重建 `task_results`；不迁移旧结果记录。
- 更新数据库结构、API、架构和 Listing 设计文档中的列名。

## 涉及文件

- `backend/app/models/task_result.py`：定义精简后的 ORM 表结构。
- `backend/app/crud/task_result.py`：按会话授权，映射短列名并推导结果元数据。
- `backend/agent/schemas/task_result.py`、`backend/agent/persistence/memory.py`：调整结果领域记录的运行上下文和时间字段。
- `backend/tests/test_postgres_task_result_crud.py`：将 SQL 返回列断言更新为新的主键名。
- `backend/migrations/009_task_results_compact_schema.sql`：重建任务结果表，不保留旧数据。
- `docs/数据库结构.md`、`docs/接口说明.md`、`docs/架构说明.md`、`docs/agents/listing/`：同步当前结构说明。
- `CHANGELOG.md`：记录未发布的数据结构变化。

## 设计决策

- 保留 `conversation_id` 作为结果归属锚点，数据库授权查询通过会话所有者过滤。
- `run_id` 继续作为写入时的瞬时上下文校验值，不再保存到 `task_results`。
- 图片、Listing 和科研结果类型根据所属会话的智能体标识推导。
- 迁移直接删除并重建任务结果表；执行后原有任务结果不可恢复。

## 潜在影响

- 应用启动使用 `create_all` 时不会修改已存在表；已有数据库需要手动执行 `009_task_results_compact_schema.sql`。
- 执行迁移会清空已有 `task_results` 数据。
