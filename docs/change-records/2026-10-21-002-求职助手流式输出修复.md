# 求职助手流式输出修复

- 日期：2026-10-21
- 变更类型：缺陷修复
- 影响范围：简历工作台求职助手的回复显示

## 背景

求职智能体已使用流式模型适配器，但共享 Runner 的实时转发白名单只有通用和基础对话智能体。`job_agent` 的模型片段被过滤，Runner 在图节点完成后才把完整回答拆成 SSE 片段，因此用户看到回复集中出现。

## 变更内容

- 将 `job_agent` 的 `agent_node` 加入共享 Runner 的用户可见流式节点白名单。
- 增加求职智能体 Runner 回归测试，要求模型的两段回复分别成为两个 `message.delta` 事件。
- 同步求职智能体说明、接口文档和项目变更摘要。

## 涉及文件

- `backend/agent/runner.py`：允许实时转发求职图的模型片段。
- `backend/tests/test_runtime.py`：覆盖求职图到 SSE 事件的流式链路。
- `backend/agents/job_agent/README.md`、`docs/接口文档.md`、`CHANGELOG.md`：说明用户可见行为。

## 设计决策

- 保持 Runner 对用户可见节点的显式白名单，避免把其他智能体的计划、工具参数或结构化草稿作为文本流暴露。

## 测试与验证

- 修复前运行 `.venv/Scripts/python.exe -m pytest -q tests/test_runtime.py::test_job_agent_forwards_model_chunks_as_separate_sse_deltas`：失败；收到一段合并文本，预期为两段。
- 修复后运行同一命令：1 通过。
- 在 `backend/` 执行 `.venv/Scripts/python.exe -m pytest -q`：172 通过，1 条第三方弃用警告。
- 执行 `docker compose -f backend/compose.yaml up -d --build backend worker`：两个镜像构建并重建容器成功。重建前 Celery 活动任务为空；数据库中另有一条多日未更新的 `listing_agent` running 记录。
- `GET http://127.0.0.1:8000/health/ready`：返回 healthy，PostgreSQL 与 Redis 均 healthy。
- 在新 Worker 容器检查 `STREAMING_RESPONSE_NODES_BY_AGENT[JOB_AGENT]`：包含 `agent_node`。

未发起真实模型对话，避免创建测试会话和调用外部模型；SSE 片段由确定性 Runner 回归测试验证。

## 潜在影响

- 求职助手的模型输出现在会在生成期间逐段送达客户端；其他智能体的流式节点配置不变。
