# 提出会话与消息表结构设计

- 日期：2026-10-03
- 变更类型：架构
- 影响范围：数据库设计文档、后续会话与消息数据模型迁移

## 背景

当前会话和消息主键由应用生成 UUID hex；消息历史依赖 `sequence` 排序，正文以文本保存。用户要求 ID 改为纯数字、删除消息排序字段、按创建时间展示历史，并将消息正文改为 JSON 格式。

## 变更内容

- 新增目标结构提案，建议会话和消息使用 PostgreSQL `BIGINT IDENTITY` 数字主键。
- 提案移除消息 `sequence`，以 `created_at` 查询并用消息 ID 在时间相同的情况下稳定分页。
- 提案将消息 `content` 定义为带版本号的 `JSONB` 对象，并给出字段、索引、SQL 和分页参考。
- 记录 API 数字字符串传输的精度考虑，以及正式迁移时需要联动的外键、前端接口和 Checkpointer 线程标识。
- 明确区分当前已实现结构与尚未应用的设计提案。

## 设计决策

- 数据库用 `BIGINT IDENTITY` 生成数值 ID；API 以十进制数字字符串承载，避免 JavaScript 对大整数的精度损失。
- 创建时间是消息历史的业务排序依据；`id` 仅用于相同时间值下的稳定排序和复合游标。
- Agent 运行 ID 维持当前 UUID 文本标识；只说明会话主键类型变化造成的外键和 Checkpointer 迁移影响，不重设计 AgentRunner。
- 本任务只交付设计提案，不更改数据库、API 或前端实现，因此不更新面向使用者的 `CHANGELOG.md`。
