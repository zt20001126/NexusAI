# 邮箱注册登录与智能体首页

- 日期：2026-10-22
- 变更类型：新功能、架构、数据模型
- 影响范围：认证 API、浏览器会话、智能体首页、简历和求职助手的账号数据归属

## 背景

为 NexusAI 增加邮箱账号能力。第一版通过邮箱验证码注册并设置密码，日常使用邮箱密码登录，忘记密码时通过邮箱验证码设置新密码。用户确认使用安全 Cookie 会话，并要求邮箱账号各自拥有独立简历。

## 变更内容

- 新增邮箱验证码、账号注册、密码登录、密码重置、登出及会话查询 API；密码使用 scrypt 并存入现有 `users.password_hash`，不新增认证 PostgreSQL 表。
- 验证码和临时 Cookie 会话状态使用现有 Redis 服务和 TTL；密码哈希指纹使密码重置前签发的会话自动失效。
- 新增 QQ SMTP SSL 发送适配器、注册与重置密码双格式邮件模板及 `.env.example` 配置；授权码由部署者填写，不进入仓库。
- 移除 HTTP 用户 API 的固定开发身份回退；`017_redis_auth_state.sql` 清理本次迭代早期创建的空认证临时表。
- 新增动态智能体首页和登录/注册/重置密码表单，复用统一智能体头像；会话失效时回到未登录入口。
- 将简历 API 与求职助手简历读取、确认写回绑定当前可信邮箱主体；旧固定主体数据不迁移、不分配。
- 更新接口、数据库、求职助手、启动配置、README 和 CHANGELOG 文档，并增加认证服务及设置测试。

## 涉及文件

- `backend/app/router/auth.py`、`backend/app/service/auth.py`、`backend/app/crud/auth.py`：认证接口、业务规则和持久化。
- `backend/infra/email_sender.py`、`backend/app/service/auth_email_templates.py`：QQ SMTP 和邮件模板。
- `backend/infra/redis_auth_store.py`、`backend/migrations/017_redis_auth_state.sql`：Redis 临时认证状态和早期空表清理。
- `backend/app/dependencies/auth.py`、`backend/app/router/resume.py`、`backend/agent/runner.py`、`backend/agents/job_agent/`：认证主体和账号级简历访问。
- `frontend/src/features/auth/`、`frontend/src/features/home/`、`frontend/src/App.tsx`、`frontend/src/shared/api/http.ts`：认证首页与浏览器会话交互。
- `README.md`、`CHANGELOG.md`、`docs/接口文档.md`、`docs/数据库文档.md`：操作与契约说明。

## 设计决策

- 登录会话使用 Redis TTL 和 HttpOnly、SameSite=Lax Cookie；生产环境默认使用 Secure。
- QQ 邮箱使用完整邮箱地址和 SMTP 授权码通过 SSL 465 端口发信；邮件分别提供纯文本和 HTML 模板。
- 既有 `nexusai-resume-owner` 简历保留原所有者；新邮箱账号从独立简历开始。

## 潜在影响

- 邮箱验证码不可用，直到部署时提供 QQ 邮箱 SMTP 授权码和 `AUTH_CODE_PEPPER`。
- 新部署不需认证表迁移；当前开发数据库已执行 017 清理迁移。其他数据库只有存在早期认证表时才需要执行。
- 登录切换后，旧固定主体简历仍留在数据库中，不能由邮箱账号访问。
