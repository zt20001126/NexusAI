# 统一智能体结构化追问规则

- 日期：2026-10-20
- 变更类型：架构
- 影响范围：Agent Runner、Listing 智能体、图片智能体、聊天题卡及追问恢复

## 背景

图片智能体与 Listing 智能体此前使用不同的题卡字段、选项结构和每轮问题数量。用户要求全项目结构化题卡统一为每轮最多 3 题，并参照 Listing 的闭合选择题结构；通用对话仍通过自然语言澄清。

## 变更内容

- 建立共享 `Question` 协议：仅支持单选和多选，每题恰好包含 4 个互不重复的 `{label, description}` 选项，问题全文放在 `title`，关闭自定义输入。
- 新增通用 `validate_question_batch()` 方法，由 Runner、Listing 计划和追问工具输入、图片追问工具输入共用；Runner 在发出 `question.required` 前再次执行同一校验。
- Runner 恢复答案和前端历史题卡统一使用当前严格问题协议；不保留旧格式题卡或旧等待运行的兼容路径。
- Listing 每轮上限从 1 题调整到共享的 3 题；提示词要求按事实准确性、合规风险和文案影响排序。
- 图片尺寸题收敛为 4 种画幅比例；原始请求已包含尺寸或面积档位时不重复询问。移除水印、seed 和参考图面积的追问题，缺少值时分别按不加水印、不传 seed 和 TokenHub 默认参考图面积处理。
- 通用智能体移除自由文本结构化追问工具，继续通过普通助手消息自然澄清。
- 前端交互题卡和历史题卡都只使用单选/多选与四个对象选项，不再保留文本题、确认题、自定义输入或字符串选项分支；界面隐藏轮次徽标和题型标签，等待回答时不显示图片参数状态提示。
- 更新 API 文档、项目 Changelog、现有受影响测试及实施方案记录。

## 设计决策

- 题目字段与批次限制由共享 schema 管理；各业务智能体只保留“问什么”和领域选项含义。
- `validate_question_batch()` 是新题的通用校验入口，避免 Listing、图片和 Runner 各自维护重复规则。
- Runner 对发题和恢复都使用 `QuestionPayload` 的相同校验规则；前端当前题卡和历史题卡共用 `Question` 类型。
- 图片尺寸菜单采用现有四种画幅比例；用户显式给出的参数仍由图片参数解析器读取。

## 潜在影响

- 新版 Listing 可能在同一轮返回最多 3 道题，单次运行仍最多 3 轮。
- 图片用户未指定画幅时仍会收到一张四选一尺寸题卡；明确指定的尺寸或面积档位会直接采用。
- 旧格式等待题卡不能通过当前恢复校验；结构化题卡仅支持单选、多选和闭合选项。
