## 2. 需求确认

### V1 范围

固定包含基本信息、教育背景、专业技能、工作经历、项目经历及统一排版设置。记录按添加顺序显示；编辑不改变位置，删除后不排序。专业技能以 `list[str]` 保存，每条通过 Tiptap 纯文本段落编辑；工作和项目富文本保存为 Tiptap JSON。首版仅有一个固定所有者和一份简历；不做版本、自动保存、多模板、AI 润色、拖拽排序、自动分页或 Word 导出。编辑时 A4 预览实时呈现当前草稿；页面和 PDF 仍限单页 A4，超出时提示用户调整内容。

## 3. 系统架构

### 模块职责

| 模块 | 计划职责 |
|---|---|
| app/dependencies/resume_owner.py | 返回固定保留主体标识 nexusai-resume-owner；不是登录或认证机制，仅适用于私有单人部署。 |
| app/middleware/request_size_limit.py | 在 JSON/multipart body 解析前按路径限制请求字节数，超限返回 413。 |
| app/router/resume.py | 接收 JSON、multipart、导出请求，注入固定单人主体，返回 envelope 或二进制；不执行 SQL。 |
| app/service/resume.py | 编排获取、整体保存、照片暂存/确认/删除和溢出错误转换；始终使用固定单人 owner。 |
| app/crud/resume.py | 在事务中按 owner_id 查询或 upsert 一条 Resume；复用 resolve_user_id。 |
| app/models/resume.py | 定义 resumes ORM 实体，不承载 HTTP DTO。 |
| app/schemas/resume.py | 定义基本信息、条目、Tiptap JSON、排版设置和请求响应 DTO；拒绝未声明字段。 |
| infra/resume_photo_storage.py | 用现有 AppSettings/OSS 配置保存、读取、验证、提升、删除照片和回收孤儿对象；Bucket 私有，不向客户端暴露对象键。 |
| app/service/resume_pdf.py | 从已保存 DTO 生成安全 HTML，调用 Playwright Chromium 输出 PDF，检查溢出和页数。 |
| bootstrap/runtime.py、bootstrap/application.py | 注入数据库、照片存储、PDF renderer 并注册 Router。 |
| frontend/src/features/resume/ | 页面、表单、API、Tiptap、草稿状态和 A4 预览。 |
| frontend/src/App.tsx | 以 hash 导航在聊天和简历间切换，支持刷新、前进和后退，不增加路由框架。 |

### 数据流

    打开页面
      -> GET /api/resume
      -> 固定单人主体 -> Router -> Resume Service -> CRUD -> PostgreSQL
      -> 返回已保存内容和排版
      -> 前端分别维护 draft 与 savedResume
      -> A4 预览实时渲染 draft

    上传照片
      -> POST /api/resume/photo
      -> 固定单人主体、有界读取文件、验证 PNG/JPEG 签名
      -> 私有 OSS 暂存区，返回随机 photo_id
      -> 前端用本地 object URL 预览草稿照片

    保存
      -> PUT /api/resume（完整 content + style_config）
      -> Pydantic 校验嵌套内容和 photo_id 归属
      -> 将新照片复制到按 photo_id 命名的不可变最终对象
      -> PostgreSQL 事务 upsert 唯一简历并切换 photo_id
      -> 提交成功后删除旧照片；失败时保留旧引用并清理新对象
      -> 仅成功后更新前端 savedResume；失败时保留旧对象和 staging 供重试

    PDF
      -> GET /api/resume/export/pdf
      -> 按固定单人 owner 读取已保存简历和照片
      -> Playwright 渲染 A4 -> 检查溢出和单页 -> application/pdf

保存前表单状态为 draft；A4 预览绑定 draft 并即时更新，页面明确显示“未保存”状态。保存失败保留 draft；后端 PDF 始终读取数据库已保存内容，前端在存在未保存修改时要求先保存，成功后才导出。照片上传失败不清空已有照片；取消或替换未提交照片时由 DELETE 清理暂存对象。

## 4. 数据库设计

### 表与所有权约束

在用户给出的六个字段外增加 owner_id，以关联既有 users.user_id。唯一约束保证首版单人 owner 只有一份简历。id 为 BIGSERIAL，不作为前端身份字段返回。

拟新增 backend/migrations/013_resumes.sql（当前 012 已被 legacy schema 迁移占用；实施前仍须检查是否有更新迁移）：

    BEGIN;

    CREATE TABLE resumes (
        id BIGSERIAL PRIMARY KEY,
        owner_id BIGINT NOT NULL
            REFERENCES users(user_id) ON DELETE CASCADE,
        content JSONB NOT NULL,
        style_config JSONB NOT NULL,
        created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
        updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
        CONSTRAINT uq_resumes_owner_id UNIQUE (owner_id),
        CONSTRAINT ck_resumes_content_object
            CHECK (jsonb_typeof(content) = 'object'),
        CONSTRAINT ck_resumes_style_config_object
            CHECK (jsonb_typeof(style_config) = 'object')
    );

    COMMENT ON TABLE resumes IS '每个用户唯一的简历内容和全局排版设置';
    COMMENT ON COLUMN resumes.owner_id IS '简历所有者，关联 users.user_id';
    COMMENT ON COLUMN resumes.content IS '基本信息、教育、技能、工作和项目 JSON';
    COMMENT ON COLUMN resumes.style_config IS '简历全局排版 JSON';

    COMMIT;

迁移只新增表，不回填数据。回滚只能在确认没有需保留的简历数据后删除表；本方案阶段不执行迁移或回滚。

建议范围：字号 8–14 pt，行高 1.0–2.0，段落间距 0–12 pt，模块间距 4–24 pt，页边距 5–30 mm，横线粗细 0.5–3 pt。字体和颜色使用枚举/正则白名单，不接受任意 CSS。默认值按截图初设，在视觉验收后调整。中文字体采用体积较小的文泉驿正黑和文鼎 PL 中楷；Chromium 镜像安装 Debian 的 `fonts-wqy-zenhei`、`fonts-arphic-ukai`，并以系统无衬线/衬线字体作为回退。

### ORM 与 Pydantic

SQLAlchemy 新增 Resume(Base)：id 为 BigInteger 自增主键；owner_id 为 BigInteger 外键且唯一；content、style_config 使用 PostgreSQL JSONB；created_at、updated_at 使用带时区 DateTime。updated_at 由 server_default=func.now() 和 onupdate=func.now() 管理。

Pydantic v2 DTO 在 app/schemas/resume.py 分层定义：

- BasicInfo：name、phone、email、intended_position、birth_month、photo_id。
- EducationItem、WorkItem、ProjectItem：id、结构化字段；工作和项目另含 TiptapDocument。
- ResumeContent：basic_info、educations: list[EducationItem]、skills: list[StrictStr]（JSON/API 与前端类型为 string[]）、works: list[WorkItem]、projects: list[ProjectItem]。
- ResumeStyleConfig：显式字段、字体 Literal/Enum、数值边界、HEX 颜色约束。
- ResumeSaveRequest：content + style_config；ResumeResponse：exists、content、style_config、created_at、updated_at。
- 请求模型 extra="forbid"；校验月份格式、邮箱、教育/工作/项目条目 ID 唯一性、技能字符串类型与长度、JSON 深度和样式范围。Resume.id、owner_id 和时间戳由服务端管理；教育/工作/项目条目的 UUID 由客户端生成并随内容提交；客户端不得提交 Resume.id、owner_id 或时间戳。

字段类型建议：

| DTO | 字段与类型 | 校验重点 |
|---|---|---|
| BasicInfo | name/phone/email/intended_position: str；birth_month/photo_id: str \| None | email 最长 254 字符；姓名 80、电话 32、求职意向 120 字符；月份为 YYYY-MM；photo_id 为随机 32 位十六进制引用。 |
| EducationItem | id: UUID；school/major/degree/start_month/end_month: str | 学校、专业、学历各最长 120 字符；月份合法且起始不晚于结束。 |
| ResumeContent.skills | list[StrictStr]（API/前端为 string[]） | 每个字符串是一条纯文本技能段落；最多 20 条，每条最多 500 个 Unicode 字符；数组顺序就是展示顺序。Tiptap 仅用于编辑，保存时取段落文本。 |
| WorkItem | id: UUID；company/position/start_month/end_month: str；content: TiptapDocument | 公司和职位各最长 120 字符；月份合法；富文本使用 allowlist。 |
| ProjectItem | id: UUID；name/role/technology_stack/start_month/end_month: str；content: TiptapDocument | 名称最长 120、角色 80、技术栈 240 字符；月份合法；富文本使用 allowlist。 |
| TiptapDocument | type: Literal["doc"]；content: list[TiptapNode] | 递归节点只允许 paragraph/text/hardBreak/bulletList/orderedList/listItem；orderedList.attrs 只允许 start 正整数。 |
| TiptapMark | type: Literal["bold", "italic", "underline"] | 不接受 link、style 或任意 HTML 属性。 |
| ResumeStyleConfig | font_family: Literal["wenquanyi_zenhei", "arphic_ukai"]；其余为受限 int/float、颜色 str 和 PageMargin | 字体、数值范围、颜色正则均与编辑控件一致。 |

教育、工作和项目条目的 UUID 在 JSON/API 中序列化为标准字符串；`skills` 不含 ID。Tiptap 字段仅用于工作和项目描述，使用递归的 Pydantic 节点模型和联合类型，不用裸 dict 放开任意节点。各列表可以为空；条目字段完成度按本节末尾的默认假设执行。

为限制数据库负载和 PDF 渲染资源，首版 DTO 采用以下硬上限，并在前后端使用同一组契约常量：

| 限制项 | 上限 |
|---|---:|
| 教育经历 / 技能 / 工作经历 / 项目 | 分别 10 / 20 / 20 / 20 条 |
| 单条技能纯文本 | 500 个 Unicode 字符 |
| 单条工作或项目富文本 | 4,000 个 Unicode 字符 |
| 工作和项目富文本合计 | 20,000 个 Unicode 字符 |
| 单份简历 JSON 节点 | 2,000 个 |
| PUT 请求体 | 256 KiB |
| 照片文件 / multipart 请求体 | 文件 5 MiB；完整请求体 6 MiB，且仅 PNG/JPEG |

HTTP 层和部署入口都限制 PUT 与照片 multipart 请求体；不能只依赖 Pydantic 校验，因为解析前的请求体也会占用内存。触顶返回稳定的 413 或 422 错误码。

## 5. API 设计

### 通用约定

JSON 成功使用项目 envelope；受控业务错误为 HTTP 状态码和 success=false/code/message。简历 Router 使用服务端固定的单人主体标识，并经 resolve_user_id 映射到 users.user_id；不调用 get_principal_id，不接受请求体 user_id/owner_id。读取、写入、照片和导出始终限定该 owner。所有简历 JSON、照片和 PDF 响应均设置 Cache-Control: private, no-store。

用户原列出 GET、PUT、POST photo、DELETE photo、GET PDF 五项。为了显示已保存的私有照片，补充 GET /api/resume/photo。POST 照片为暂存；DELETE 只清理当前主体尚未提交的暂存对象；已保存照片随 PUT 将 photo_id 置 null 后删除。

### 5.1 GET /api/resume — 获取简历

- 请求：无参数。
- 未保存时 HTTP 200 返回 defaults，不创建 users/resumes 行：

    {
      "success": true,
      "data": {
        "exists": false,
        "content": {
          "basic_info": {
            "name": "", "phone": "", "email": "",
            "intended_position": "", "birth_month": null, "photo_id": null
          },
          "educations": [], "skills": [], "works": [], "projects": []
        },
        "style_config": {
          "font_family": "wenquanyi_zenhei",
          "font_size_pt": 10,
          "line_height": 1.4,
          "paragraph_spacing_pt": 4,
          "section_spacing_pt": 12,
          "page_margin_mm": {"top": 14, "right": 14, "bottom": 14, "left": 14},
          "heading_color": "#1677FF",
          "divider_color": "#1677FF",
          "divider_width_pt": 1
        },
        "created_at": null,
        "updated_at": null
      }
    }

- 已保存时 exists=true，返回数据库内容、排版和 ISO-8601 时间戳。
- 流程：取得服务端固定单人主体 → resolve_user_id(create=false) → 无用户/无行时构造初始化 DTO；有行时只查询固定 owner_id → Pydantic 响应 DTO。
- 错误：数据库故障用现有受控服务错误处理，不暴露 SQL。GET 不写数据库。

### 5.2 PUT /api/resume — 整体保存

- 请求：application/json；完整 content 和 style_config，不支持按模块局部更新，不包含 owner_id、id 或时间戳。
- 请求结构：

    {
      "content": {
        "basic_info": {
          "name": "张三", "phone": "13800000000",
          "email": "zhangsan@example.com",
          "intended_position": "后端开发工程师",
          "birth_month": "1998-05",
          "photo_id": "f4db6c4a9b304340a02f29361d03d30d"
        },
        "educations": [], "skills": [], "works": [], "projects": []
      },
      "style_config": {
        "font_family": "wenquanyi_zenhei", "font_size_pt": 10,
        "line_height": 1.4, "paragraph_spacing_pt": 4,
        "section_spacing_pt": 12,
        "page_margin_mm": {"top": 14, "right": 14, "bottom": 14, "left": 14},
        "heading_color": "#1677FF", "divider_color": "#1677FF",
        "divider_width_pt": 1
      }
    }

- 成功 HTTP 200：success=true，data 包含 exists=true、数据库确认的 content/style_config 和时间戳。
- 流程：先完成 Pydantic 和请求体大小校验 → resolve_user_id(固定单人主体, create=true) → 若请求 photo_id 与数据库当前值相同则不搬动对象；若更换为新 photo_id，则验证 staging 并复制到以 photo_id 命名的不可变最终对象 → 在一个 SQLAlchemy transaction 按唯一 owner_id 插入/更新整行 → 事务成功后删除旧最终对象和已消费 staging；DB 事务失败时保留旧对象和 staging 以便重试，并删除新最终对象。若进程在对象复制或旧对象清理期间中断，回收逻辑只删除数据库当前 photo_id 未引用且最后修改时间超过 24 小时的最终对象。
- 错误：字段/嵌套/范围/技能字符串/Tiptap 校验错误 422；请求体超限 413；教育、工作或项目条目 ID 重复时返回 422；照片 ID 不存在或不是本单人主体暂存对象 404；OSS 未配置 503、OSS 故障 502；DB 故障返回受控错误。每次读写均包含固定 owner_id 谓词。

### 5.3 POST /api/resume/photo — 上传或更换证件照

- 请求：multipart/form-data 字段 file；仅 PNG/JPEG，最大 5 MiB。文件名和请求 Content-Type 不作为类型证明；检查真实文件签名，并最多读取 max_bytes+1 字节。
- 成功 HTTP 200：

    {
      "success": true,
      "data": {
        "photo_id": "f4db6c4a9b304340a02f29361d03d30d",
        "mime_type": "image/jpeg",
        "file_size": 345678
      }
    }

- 流程：固定单人主体 → 有界读取和签名校验 → 写入私有 OSS staging 前缀 → 返回随机 photo_id。该步骤不改 resumes 或已保存预览；前端用本地 object URL 显示待提交照片。
- 错误：413 超限；415 空文件、类型不允许或签名不匹配；OSS 未配置 503、存储失败 502。日志不记录简历字段、照片内容或密钥。

### 5.4 DELETE /api/resume/photo?photo_id=... — 清理暂存照片

- 请求：必填 photo_id 查询参数，用于取消、删除或替换尚未 PUT 保存的照片。
- 成功 HTTP 200：success=true，data={photo_id,deleted:true}。可重复执行；不存在或不属于当前主体统一 404。
- 流程：固定单人主体 → 只在 staging 前缀查找/删除对象；不更改已保存简历。删除已保存照片由 PUT 的 basic_info.photo_id=null 完成。
- 错误：400 ID 格式错误；404 不存在或已提交；OSS 未配置 503、操作失败 502。

### 5.5 GET /api/resume/photo — 读取已保存证件照（补充操作）

- 请求：无参数，不接受客户端对象键。
- 成功：返回图片字节，Content-Type 为已验证的 PNG/JPEG；设置 X-Content-Type-Options:nosniff 和 Cache-Control: private, no-store。
- 流程：固定单人主体 → 读取唯一简历的 photo_id → 存储适配器按固定 owner 和 photo_id 读取不可变对象 → 返回字节。不存在简历/照片 404。
- 错误：404、OSS 未配置 503、存储读取失败 502。草稿照片由前端本地 URL 展示；PUT 成功后再加载此接口。

### 5.6 GET /api/resume/export/pdf — 导出 PDF

- 请求：无 body 或待导出 JSON，确保只生成已保存数据。
- 成功：返回 application/pdf，Content-Disposition: attachment; filename="resume.pdf"，不保存到后端持久目录。
- 流程：固定单人主体 → CRUD 读取已保存简历 → 读取私有照片到内存 → HTML 转义并嵌入照片 data URL → Playwright Chromium 渲染 A4 → 预检溢出并以 pypdf 确认一页 → 回传 PDF。
- 错误：未保存简历 404；超出 A4 422，code=RESUME_PAGE_OVERFLOW；OSS 502/503；Chromium 超时/不可用 503/500。溢出返回 JSON 错误，前端提示“内容超过单页 A4，请减少内容或调整排版”，不返回静默截断 PDF。

### 页面与组件拆分

    └── ResumePage

        └── ResumeEditorPanel

            ├── ProjectsEditor + RichTextEditor

桌面端使用截图中的三栏；窄屏折叠导航并切换/堆叠编辑区和预览。样式放 features/resume/styles/resume.css，复用现有蓝色、边框、焦点状态和按钮风格，不加通用 UI 框架。图标复用资源或内联 SVG，不增加图标依赖。

### 状态与交互

- useResumeEditor 管理加载状态、draft、savedResume、选中模块、保存状态、照片上传和字段错误；深拷贝避免 draft 引用污染 preview。
- 初始加载、空简历、加载失败/重试分别展示。空态 draft 用服务端 defaults，未保存时 A4 预览显示空白引导。
- 模块导航只切换面板。教育、工作和项目新增时创建 UUID，编辑保留 ID/位置；技能不创建持久化 ID，按数组位置增删改并保留其余条目顺序。技能编辑器可使用仅存在于前端内存的行 key 稳定维护 Tiptap 实例，该 key 不进入 content/API。
- Save 发送完整 PUT；成功才用服务端响应更新 savedResume；失败保留 draft。保存期间禁止重复保存。
- A4 预览实时使用 draft，明确显示“未保存”状态和溢出提示；布局和样式与 PDF 共用设计 token。
- Export 只用服务端已保存数据。draft 有改动时提示“保存并导出”；用户确认后先 PUT，成功再下载 PDF，失败时保留 draft 且不导出。
- 离开有未保存改动的页面前提示；无自动保存。
- 替换/删除/保存成功/卸载时 revoke 本地照片 object URL。
- 在 AgentDirectory 增加入口；App 使用 hash path 切换聊天/简历，支持直接刷新，不新增 Router 依赖。

### Tiptap 方案

仓库没有编辑器。采用 Tiptap React；所有 @tiptap 包锁定同一主版本并提交 lockfile。工作和项目描述的前端扩展与后端 DTO 共用同一白名单：仅 doc、paragraph、text、hardBreak、bulletList、orderedList、listItem 节点，以及 bold、italic、underline marks。配置 StarterKit 禁用白名单外的 heading、blockquote、codeBlock、horizontalRule、code、link、strike 等扩展；若所选 StarterKit 版本已包含 underline，不再单独注册同名扩展。工作和项目的工具栏提供加粗、斜体、下划线、有序/无序列表、撤销和重做；每条工作内容和项目描述各自保存一份 doc JSON。技能项也使用独立的 Tiptap 编辑器，但只启用 doc、paragraph、text，不显示富文本工具栏；保存时读取段落文本并写入 `skills: list[str]`，因此技能格式是纯文本。预览将工作和项目的受限 JSON 渲染为结构化内容，将技能字符串转义后逐项渲染为独立段落，不直接插入用户提交的任意 HTML。

依赖建议为 @tiptap/react、@tiptap/pm、@tiptap/starter-kit，以及与所选主版本匹配的扩展；不要在 StarterKit 已包含 underline 时重复安装/注册。实施时固定精确版本并验证编辑、PUT/GET round-trip 和预览格式一致：[React 集成](https://tiptap.dev/docs/editor/getting-started/install/react)、[JSON 持久化](https://tiptap.dev/docs/editor/core-concepts/persistence)、[StarterKit 配置](https://tiptap.dev/docs/editor/extensions/functionality/starterkit)。

## 7. PDF 导出设计

### 推荐方案及兼容性

推荐后端 Playwright Python + Chromium：提供规定的 GET PDF 接口，读取已保存数据，并以服务端错误协议拒绝超限内容。项目当前 Python 3.12；Playwright Python 文档要求 Python 3.8+ 并列出 Linux 支持系统；当前容器基于 python:3.12.13-slim。接入需在 backend/requirements.txt 固定 Playwright 版本，在 backend/Dockerfile 安装匹配 Chromium 和系统库，并配置浏览器目录供非 root app 用户读取。浏览器二进制需与 Playwright 版本匹配；会增加镜像体积、构建时间和运行内存，需限制导出并发和超时。项目没有 Playwright，所以并非零配置复用，但与 Python/Linux 容器兼容且可控。[Playwright 系统要求](https://playwright.dev/python/docs/intro#system-requirements)、[浏览器安装与版本匹配](https://playwright.dev/python/docs/browsers)。

page.pdf() 由 Chromium 按 print CSS 生成，支持 A4、背景和 CSS 页面尺寸；使用 prefer_css_page_size、print_background、-webkit-print-color-adjust 对齐纸张及标题颜色。[Playwright Python page.pdf](https://playwright.dev/python/docs/api/class-page#page-pdf)。中文字体随镜像安装文泉驿正黑和文鼎 PL 中楷；渲染前等待 document.fonts.ready 和图片加载。照片作为内存 data URL，不依赖 Chromium 访问 OSS 或公网。

替代方案：
- 浏览器打印：最接近当前 React 预览、后端依赖最少，但不便于提供指定的 GET PDF 服务端响应和一致的溢出错误，不选作主方案。
- WeasyPrint/ReportLab：项目没有现成依赖，需要另建 PDF 引擎并处理 CSS/富文本、中文字体、图片布局，与浏览器预览更难保持一致，不选。
- 前后端 HTML 模板是两条渲染链。V1 使用同一 content/style DTO、截图布局和设计 token，并做 PDF 截图对照；若审核要求像素级一致，应抽取共享模板/渲染资源，该工作不在 V1 范围。

### 单页与溢出控制

1. CSS @page 固定 A4；页面盒子按毫米尺寸和配置页边距设置；不设置 page_ranges，不以 overflow:hidden 隐藏溢出。
2. PDF HTML 只从服务端 DTO 生成；普通字段 HTML 转义，富文本按允许节点递归生成，颜色/字体白名单化。Renderer 不访问用户 URL，避免 SSRF。
3. 加载后等待字体和照片，再比较简历内容边界与 A4 可用区域。超出即返回 422。生成后用已有 pypdf 检查页数必须为 1；非一页也拒绝成功。
4. 标题、横线、字号、字体、行距、段距、模块距和页边距来自 style_config。证件照采用固定区域和裁切规则；无照片时不使用外部头像。
5. PDF 在内存生成；成功、溢出、超时和异常均关闭浏览器/上下文。限制渲染并发、超时和照片大小。

### V1 默认值与部署边界

- 截图仅将姓名、电话、邮箱标为必填；建议求职意向和出生年月可空。每类列表项如有填写，则校验名称/学校/日期等字段；数组本身允许为空。
- 日期按截图统一 YYYY-MM，起始不能晚于结束。V1 不提供“至今”，因需求列出开始和结束时间。
- 字体默认文泉驿正黑，备选文鼎 PL 中楷；导出容器安装对应 Debian 字体包。
- 样式默认值和范围按第 4 节建议，结合截图验收后锁定。
- 首版不接外部身份或登录系统。简历 Router 使用服务端固定主体标识 nexusai-resume-owner，所有访问落到同一份简历；该模式只部署在本机、私有网络或 VPN，公网匿名访问不在首版支持范围。
- 不引入版本字段；多个标签页以最后成功 PUT 覆盖。如需避免覆盖，可后续评估 updated_at 条件更新，不纳入 V1。
- OSS 和 PostgreSQL 不能原子提交：照片使用固定 owner 的 staging 和按 photo_id 命名的不可变最终对象；数据库引用提交成功后再删除旧对象。失败时保留旧引用和 staging，孤儿对象由 GET/PUT 中可重试的回收逻辑清理（只删除未引用且超过 24 小时的对象）；staging 配置 7 天生命周期过期。日志不得包含简历字段、照片内容或密钥。
