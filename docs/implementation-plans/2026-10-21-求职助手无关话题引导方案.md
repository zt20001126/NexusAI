# 求职助手无关话题引导实现方案

> 日期：2026-10-21（Asia/Shanghai）
> 状态：实现已完成
> 需求确认：已澄清；含已标注的非阻塞假设

## 1. 目标与背景

- **要解决的问题：** 求职助手目前的行为指令强调求职建议与能力边界，但没有明确规定遇到无关话题时如何回应。
- **功能目标：** 当用户提出与求职无关的问题时，助手简短说明职责范围，并引导用户提供与求职相关的信息。
- **预期最终效果：** 用户询问天气、烹饪等无关内容时，助手不继续回答该话题，而是说明自己可帮助岗位方向推荐、求职规划、经历表达和面试准备，并给出一条易回答的求职信息提示。

## 2. 已确认需求

- **使用者 / 调用方：** 在简历工作台使用 `job_agent` 的求职者。
- **触发方式：** 用户提交一条与求职、职业发展、简历经历或面试准备无关的消息。
- **输入：** 当前轮用户文本及 Checkpointer 保留的会话上下文。
- **输出：** 求职助手职责说明和引导用户提出求职相关问题的简短回复。
- **主流程：**
  1. 模型结合当前消息和会话历史判断用户意图是否属于求职助手职责。
  2. 如果无关，直接说明职责并给出可回答的求职信息示例，不调用求职推荐或提问工具。
  3. 如果相关，继续现有求职对话、追问和岗位建议流程。
- **业务规则与边界：**
  - 求职相关范围沿用当前产品定位：求职目标、岗位方向、职业经历表达、面试准备和求职规划。
  - 无关话题不提供实质答案；职责说明控制在简短自然语言中，并给出清晰的下一步。
  - 不因用户没有提供年龄或学历而触发范围引导；这不是意图判断条件。
  - 无关输入的回复不应调用 `ask_user_questions` 或 `recommend_job_roles`。
- **异常行为：** 不新增工具、外部服务或持久化状态；模型调用仍使用现有错误处理。
- **权限与数据范围：** 不改变现有主体校验、会话归属或数据访问范围。
- **约束：** 不增加确定性关键词分类器；避免将“岗位要求”之外的自然语言求职问题误判为无关。

## 3. 范围

- **本次包含：** 明确模型对职责范围的判断规则、无关话题回复方式和面向用户的引导示例；增加行为回归验证；同步求职助手文档、接口说明、`CHANGELOG.md` 和任务级变更记录。
- **本次不包含：** 新增意图识别模型、关键词分类逻辑、API、前端控件、数据库字段或新工具；不扩展求职助手的业务能力。

## 4. 需求澄清记录

需求和代码库信息已足够形成方案。用户已明确要求无关话题时说明职责并引导回答。

| 需要确认的问题 | 确认结果 | 对方案的影响 |
|---|---|---|
| 如何定义职责范围 | 沿用现有求职助手定位和已实现的岗位方向建议 | 使用提示词描述职责边界，不另建职责目录或分类器。 |
| 用户同时提出求职问题和无关问题时如何处理 | 非阻塞假设：先回答求职相关部分；若无法兼顾，再简短引导回求职主题 | 不把整条混合消息直接判为无关。 |
| 仅打招呼或表达不完整时如何处理 | 非阻塞假设：礼貌回应，并说明能提供的求职帮助及可提供的信息 | 作为边界测试，不把简单问候当作普通无关问题拒绝。 |

## 5. 当前代码结构与依据

| 现有文件 / 模块 | 当前职责 | 与本功能的关系 |
|---|---|---|
| `backend/agents/job_agent/prompts/system.md` | 定义求职助手角色和基本能力边界 | 增补职责范围和无关话题处理原则。 |
| `backend/agents/job_agent/prompts/agent.md` | 定义对话、追问、岗位建议和事实约束 | 增补意图判断、引导话术和相关/无关/混合输入规则。 |
| `backend/agents/job_agent/prompts/loader.py` | 按固定顺序组合上述 Markdown 提示词 | 提示词变更会通过现有加载流程进入模型调用，无需修改加载器。 |
| `backend/agents/job_agent/nodes/agent_node.py` | 每轮以系统提示词和会话消息调用模型 | 现有模型节点可基于上下文执行语义判断并直接回复。 |
| `backend/agents/job_agent/nodes/input_node.py` | 校验本轮消息类型、空白和长度 | 不负责业务意图，不建议将关键词分类塞入输入校验。 |
| `backend/agents/job_agent/graph.py` | 模型决策后路由到工具或最终回答 | 模型直接回复时现有图会进入 `output_node`；无关回复不需要新节点。 |
| `backend/tests/test_job_agent.py` | 验证求职图、工具、追问恢复与推荐路径 | 增补无关话题、问候、相关话题与混合话题的行为验证。 |
| `backend/agents/job_agent/README.md`、`docs/接口文档.md` | 说明求职助手能力与用户可见边界 | 同步说明无关输入会收到职责提示。 |

当前数据流为 `input_node → agent_node → (tool_node → agent_node)* → output_node`。模型若直接产生职责提示，不会进入提问或岗位推荐工具；回复继续经现有输出节点和共享 Runner/SSE 返回。

## 6. 架构设计

### 模块职责与边界

| 模块 | 职责 | 依赖方向 / 边界 |
|---|---|---|
| `prompts/system.md` | 明确助手面向求职的职责和不处理无关问题的原则 | 作为现有模型节点系统提示的一部分，不引入新运行时依赖。 |
| `prompts/agent.md` | 定义意图判断、相关请求继续处理、无关请求引导和混合请求策略 | 约束现有模型行为；不负责 API 或会话状态。 |
| `tests/test_job_agent.py` | 检查提示词约束、工具选择边界和既有求职流程 | 使用现有离线模型模式；必要时配合真实模型人工抽样验证。 |

### 关键流程

```text
用户消息 -> input_node 输入校验 -> agent_node 结合上下文判断意图
                                      ├─ 求职相关 -> 现有对话/追问/岗位建议流程
                                      └─ 无关内容 -> 职责说明 + 求职信息引导 -> output_node
```

使用现有模型节点完成语义判断，避免关键字表误判表达方式多样的求职问题。无关输入不需要暂停运行或持久化额外状态；混合输入优先保留其中的求职需求。

## 10. 分步实施计划

### 步骤 1：定义求职职责边界和引导回复

- **目的：** 让模型稳定区分求职请求与无关请求，并在无关输入时给出明确的下一步。
- **涉及文件：** `backend/agents/job_agent/prompts/system.md`、`backend/agents/job_agent/prompts/agent.md`。
- **实施内容：** 列明支持的求职主题；要求无关请求不作实质回答，简短说明职责并邀请用户提供求职方向、专业、技能或经历；定义问候和混合消息处理；指明无关输入不调用提问或推荐工具。
- **前置依赖：** 无。
- **验收标准：**
  - [ ] 无关请求得到职责说明和具体求职引导，不包含对无关问题的实质解答。
  - [ ] 求职岗位推荐、简历经历表达、面试准备和求职规划不被归为无关。
  - [ ] 单纯问候得到自然回应和能力介绍；混合请求优先处理求职部分。
- **验证方式：** 检查提示词约束；使用离线脚本覆盖图路由，并对真实模型抽样做人工验收。

### 步骤 2：增加职责边界回归验证

- **目的：** 防止后续提示词修改导致越界回答或误拒求职请求。
- **涉及文件：** `backend/tests/test_job_agent.py`。
- **实施内容：** 增加天气/常识类无关输入、问候、典型求职问题、混合请求的测试用例；断言无关输入作为普通回复完成，不等待题卡且不触发推荐工具。
- **前置依赖：** 步骤 1。
- **验收标准：**
  - [ ] 离线测试模型模拟无关输入时，响应为 `completed`，不返回 `questions`。
  - [ ] 相关求职请求仍能进入岗位推荐工具或原有求职对话路径。
- **验证方式：** 执行求职智能体专属 pytest，并运行完整后端测试套件；报告已有或新增失败，不掩盖无关失败。

### 步骤 3：同步能力说明与变更记录

- **目的：** 让代码说明、用户可见文档和项目变更摘要一致。
- **涉及文件：** `backend/agents/job_agent/README.md`、`docs/接口文档.md`、`CHANGELOG.md`、当日任务级变更记录。
- **实施内容：** 更新职责边界描述；任务级记录只写实际完成行为、测试结果和模型分类的已知限制；确认记录序号未被占用。
- **前置依赖：** 步骤 1–2。
- **验收标准：**
  - [ ] 文档说明助手会对无关话题进行职责引导，且不声称支持未实现能力。
  - [ ] `[Unreleased]` 和任务记录同步，任务记录测试结果来自实际运行。
- **验证方式：** 审阅相关文档与 `git diff --check`。

## 12. 风险、假设与运行考虑

- **非阻塞假设：** 本方案将“无关”解释为不属于求职、职业规划、岗位、简历经历或面试准备的实质请求；仅问候视为需要介绍职责的开场。混合输入优先回答求职相关部分。
- **主要风险及应对：** 分类由提示词引导的模型完成，可能误判边缘话题；提示词明确相关范围、给出正反例，并通过相关请求回归和真实模型抽样降低风险。
- **安全 / 隐私 / 性能 / 可观测性：** 不新增资料存储、外部调用或日志；引导用户只提供完成求职建议所需的信息。
- **发布、迁移或回滚：** 无迁移；随现有后端部署。若观察到相关请求被误判，调整提示词规则和边界样例即可回滚行为。
