# 统一智能体结构化追问规则实现方案

> 日期：2026-10-20（Asia/Shanghai）
> 状态：实现已完成，测试未运行
> 需求确认：已澄清；按本方案采用四种画幅选项和参考图面积默认值

## 1. 目标与背景

- **要解决的问题：** 图片智能体和 Listing 智能体使用不同的结构化追问规则。图片题卡目前接受 7 个尺寸选项、自由文本题和 3 个参考图面积选项；Listing 使用单选/多选、每题 4 个结构化选项、完整题目写在 `title` 中。
- **功能目标：** 让项目中的结构化题卡遵循同一题目结构、每轮题数上限和追问轮数上限；保留通用对话通过自然语言继续澄清的能力。
- **预期最终效果：** 所有新发出的结构化题卡每轮有 1–3 题，最多追问 3 轮；每题使用单选或多选、恰好 4 个 `{label, description}` 选项，`title` 是完整问题，不返回 `prompt`，不允许自由输入。

## 2. 已确认需求

- **使用者 / 调用方：** 图片智能体、Listing 智能体和聊天题卡前端；共享 Agent Runner 校验所有结构化追问。
- **触发方式：** 智能体认为需要用户选择补充信息时发出 `question.required` 事件。
- **输入：** 后端生成的结构化问题；用户以选项标签提交单选答案，或以标签数组提交多选答案。
- **输出：** 沿用现有 `question.required` SSE 事件、`question_batch` 历史消息和追问恢复接口，不改路由或事件名称。
- **主流程：**
  1. 业务智能体按领域规则判断是否仍缺必要信息。
  2. 后端按共享问题模型校验每轮 1–3 道题、题型、四个选项和字段结构。
  3. 前端显示统一题卡并提交所选标签。
  4. Runner 最多恢复 3 轮；第三轮回答后不再发新题，由业务智能体按已知信息完成任务或采用既定默认值。
- **业务规则与边界（用户已确认）：**
  - 每轮最多 3 道题；不足 3 题时不为凑数增加问题。
  - 每次运行最多 3 轮；最多可有 9 道题，但是否继续追问由业务智能体决定。
  - 题型限 `SingleChoice`、`MultiChoice`；每题恰好 4 个互不重复的选项对象，包含 `label` 和 `description`。
  - `title` 必须包含完整题目；新问题不带 `prompt` 或 `placeholder`；`allow_custom_input` 固定为 `false`。
  - 只有当前答案无法从请求、附件或之前答案中获得，且对任务有实际影响时才追问；已有值不重复询问。
  - Listing 保留其领域规则：按准确性、合规风险和文案影响排序，未知或不适用项不能被当作事实。
  - 图片智能体不再追问水印文案或 seed；只采用用户主动提供的值。未提供水印时不加水印，未提供 seed 时沿用服务端随机种子策略。
  - 通用对话允许用自然语言澄清，不再生成自由文本结构化题卡；科研、劳动法和文献解读流程通过普通对话接收问题，不引入新的结构化题卡。
- **图片参数实现决策：** 尺寸题保留并压缩为四种现有画幅比例；面积档位继续从原始请求读取。`resize_max_pixels` 是可选参数，用户明确给值时读取，未给值时采用 TokenHub 默认值，不单独追问。该参数未传时默认 1,048,576，依据[腾讯云 TokenHub Hy 生图调用指南](https://cloud.tencent.com/document/product/1823/135745)。
- **异常行为：** 新格式不符合共享 schema 时按现有 `INVALID_QUESTION_PAYLOAD` 失败处理；第 4 轮问题按现有 `QUESTION_ROUND_LIMIT` 失败处理；答案只能匹配当前问题 ID 与选项标签。
- **权限与数据范围：** 不改变身份校验、所有权检查、会话数据或任务结果访问范围。
- **约束：** 不改 SSE 事件名、API 路由、数据库表或结果 JSON；旧格式题卡和等待运行不属于新协议的兼容范围。

## 3. 范围

- **本次包含：** 共享后端问题 schema 与 Runner 校验；Listing 每轮题数；图片参数提问策略；通用智能体自由文本题卡退出结构化暂停流程；前端交互题卡和历史题卡类型；API 文档、项目变更日志及任务级变更记录。
- **本次不包含：** 普通模型对话中自然语言问题的限制；调整 Listing 事实识别、选项质量和结果生成原则；改数据库表、迁移、SSE 事件名称或任务结果结构。

## 6. 架构设计

### 模块职责与边界

| 模块 | 职责 | 依赖方向 / 边界 |
|---|---|---|
| `agent.schemas.question` | 成为所有结构化题卡的唯一标准；由 `validate_question_batch()` 集中执行题型、题数、选项数、字段及答案校验 | Listing、图片和 Runner 调用同一共享入口；共享层不引入业务参数。 |
| Listing Agent | 保留领域问题优先级和商品事实规则，使用共享题目结构，每轮输出不超过 3 题 | Listing 提示词与 schema 约束模型输出，Runner 再做协议校验。 |
| Image Agent | 保留尺寸确认；把参数选项改为统一结构；自由值由原始请求解析，缺省项采用现有默认策略 | 参数解析与 TokenHub 字段映射仍留在 image_agent。 |
| Agent Runner | 对新问题、恢复答案使用相同严格校验 | 不依赖具体题卡 UI；事件和答案持久化字段保持不变。 |
| Chat 前端 | 当前问题、待答问题和历史题卡都只渲染单选/多选四选项 | API 类型仅表达当前问题协议。 |
| 通用智能体 | 通过普通助手消息自然追问，不生成自由文本暂停题卡 | 移除 `ask_user_question` 的暂停工具注册；其余工具能力不变。 |

### 关键流程

```text
Listing / Image Agent -> AgentRunner 严格校验 QuestionPayload -> question.required + question_batch
用户选择 label -> ResumeRequest -> Runner 校验答案 -> 原业务智能体继续执行
通用对话 -> 普通自然语言澄清，不进入 question.required 流程
```

共享 schema 负责所有结构化题卡的统一边界，避免 Listing 与图片智能体分别维护同一份字段规则。历史题卡和当前等待问题也按此 schema 读取和恢复。

## 9. 接口与数据变更

- `question.required` 和 `question_batch` 的字段名不变；`questions[]` 项不包含 `prompt`、`placeholder`，选项统一为 4 个 `{label, description}` 对象。
- 结构化答案仅使用选项标签字符串或字符串数组；单选、多选答案仍提交 `label`，不把描述文本提交给后端。
- 不新增数据库列或迁移。`pending_questions` 与 `question_batch` 仍保存在现有 JSON 元数据和消息内容中。
- 旧格式题卡和旧 waiting run 不在支持范围内；恢复运行与读取历史题卡都必须满足当前统一协议。
- 普通自然语言对话不经过 `question.required`，不受四选项约束。
- 外部客户端调用恢复接口时，答案必须使用当前题卡的选项标签。

## 10. 分步实施计划

### 步骤 1：定义共享题卡契约与严格恢复校验

- **目的：** 让所有结构化题卡只有一个后端模型和恢复协议。
- **涉及文件：** `backend/agent/constants.py`、`backend/agent/schemas/question.py`、`backend/agent/runner.py`、`backend/app/schemas/agent.py`。
- **实施内容：** 固定 4 个对象选项；仅支持 SingleChoice/MultiChoice；每批最多 3 题；收敛答案值；新题和当前 `pending_questions` 都走严格校验。
- **前置依赖：** 无。
- **验收标准：**
  - [ ] 1–3 道题且每题四个有效对象选项可通过；0 题、4 题、非选择题、字符串选项、少/多于四项、重复标签及自由输入均不能通过。
  - [ ] 选项答案只接受选项标签；多选最多四项。
  - [ ] 恢复时校验当前问题批次及选项标签；旧格式问题不属于支持协议。
- **验证方式：** 扩展共享 schema、Runner 恢复和 API DTO 的单元测试。

### 步骤 2：让 Listing 每轮最多规划三题

## 12. 风险、假设与运行考虑

- **非阻塞假设：** 尺寸题的四选项建议采用当前已支持的 1:1、3:4、4:3、16:9 四种比例；1K、1.5K、2K 面积档位继续可通过原始请求明确指定。若希望菜单保留面积档位，可在审阅时调整四个菜单值。
- **主要风险及应对：**
  - 旧格式等待运行无法按当前结构恢复；部署时应让前后端使用同一版本。
  - Listing 每轮从 1 题调整到最多 3 题，单次运行最多可能确认 9 个信息点；提示词仍只要求必要问题并按风险排序。
  - 移除通用智能体暂停工具会改变其显式“结构化收集目标”行为；用户已确认通用对话可以用自然语言追问。
  - 新版 Listing 批次可能不被回滚后的旧 Listing schema 接受；发布和回滚需作为同一应用版本协调。
- **安全 / 隐私 / 性能 / 可观测性：** 不新增用户数据或日志内容；保持答案长度和问题 ID 限制。
- **发布、迁移或回滚：** 无数据库迁移；部署需同时更新后端与前端。旧格式 waiting runs 不再兼容恢复；回滚需考虑新版 Listing 批次最多三题这一差异。
